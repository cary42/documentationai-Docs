## Create and manage profile fields

Profile fields store the custom details your camp tracks about people in Campium, such as school, grade, allergies, bus route, or staff department. Each field has a name, a field type, and answers saved per person.

Built-in fields such as name, email, user type, and status are separate from profile fields. Use Profile Fields for the data your organization defines and maintains.

<Callout kind="info" collapsed="false" color="#ef4444">
  Think of Profile Fields as your camp's data dictionary. You define the field once, then Campium can use that same field across profiles, forms, reports, the health report, and Staff Hub.
</Callout>

### Field types

Profile fields support these field types:

- **Text** - freeform answers such as classroom name, physician, or notes

- **Date** - date-based answers such as graduation date or last physical

- **Multiple Choice - Choose One** - a single selection from a list, such as grade or bus route

- **Multiple Choice - Choose Many** - multiple selections from a list, such as allergies or activity interests

- **Ranked Choice** - families put options in order (1st choice, 2nd choice, 3rd choice) instead of only selecting them. See [Ranked Choice fields](#ranked-choice-fields).

- **Link to a User** - links this field to another person in Campium. When you choose this type, you pick the target user type the field points to: **Staff**, **Camper**, or **Guardian** (for example, linking a camper to an assigned counselor)

## Find Profile Fields in Admin

Open **Admin → Profile Fields** at `/admin/profile-fields.php`. You need the **Profile Fields** permission, listed as `custom_module`, to access the page.

The page opens to a searchable table of all profile fields in your database. From there, you can add fields, edit existing ones, manage options, review usage, and control access.

## Understand the main screen

The main Profile Fields screen gives you a high-level view of every field and how it is configured.

| Column            | What it shows                                                            |
| ----------------- | ------------------------------------------------------------------------ |
| **Field Name**    | The label staff see for the field                                        |
| **User Type**     | Which people the field applies to: Campers, Parents, Staff, All Users, or **Family** (one shared answer) |
| **Field Type**    | Text, Date, Choose One, Choose Many, Ranked Choice, or Link to a User     |
| **Health report** | A checkmark if the field appears on health reports                       |
| **Description**   | An internal note about the field - not seen by families                  |
| **Status**        | Whether the field is Active or Inactive                                  |

Each row also includes a dropdown menu (⋮) with actions for that field. Not every action appears on every row — visibility depends on the field type and whether it is a system field.

| Action                          | What it does                                        | When it appears                              |
| ------------------------------- | --------------------------------------------------- | -------------------------------------------- |
| **Edit Profile Field**          | Open the field settings to make changes             | Editable fields only                         |
| **Options**                     | Add, reorder, or manage answer choices              | Choose One, Choose Many, and Ranked Choice fields |
| **View Usage in Forms/Reports** | See everywhere the field is referenced              | Always visible                               |
| **Remove Everyone's Response**  | Clear saved answers while keeping the field         | When removal is allowed for the field        |
| **Delete Profile Field**        | Permanently remove the field definition             | Deletable fields only (blocked if in use)    |
| **Copy Field**                  | Duplicate the field setup without copying answers   | Non-primary fields only                      |
| **Access Rights**               | Control which staff roles can see this field's data | When access rights are enabled for the field |

## Add a new field

Create a new field when you need to track information that Campium does not provide as a built-in field.

### Field settings

Use the Add New Field form to define the field.

<ParamField body="Field name" param-type="string" required="true" deprecated="false" show-location="false">
  The label staff see. Keep it under 50 characters, do not use commas, and do not prefix the user type in the name. A field name cannot be **Family ID** and cannot start with **camper** or **staff**.
</ParamField>

<ParamField body="Signature field" param-type="boolean" required="false" deprecated="false" show-location="false">
  Turns the field into a signature-style field when that option is available in your setup.
</ParamField>

<ParamField body="Type of Field" param-type="string" required="true" deprecated="false" show-location="false" enum="Multiple Choice - Choose One,Multiple Choice - Choose Many,Text,Date,Link to a User,Ranked Choice">
  Sets the answer format for the field. **Link to a User** connects the field to another person; when you pick it, choose the target user type the link points to (**Staff**, **Camper**, or **Guardian**). **Ranked Choice** asks people to order options; when you pick it, set **How many can they rank?**
</ParamField>

<ParamField body="How many can they rank?" param-type="string" required="false" deprecated="false" show-location="false">
  Shown only for **Ranked Choice**. Set **At least** (minimum ranks required) and **Up to** (maximum ranks allowed). Set both to the same number to ask for an exact count, such as ranking exactly three activities. Leave **At least** at 0 if ranking is optional.
</ParamField>

<ParamField body="Used for" param-type="string" required="true" deprecated="false" show-location="false">
  Chooses which user types the field applies to. Use a specific type, make the field available to all users, or choose **Family** for one answer the whole household shares. On the form this label is **This field will be used for**. Helper text for Family: **Family means one answer the whole family shares**.
</ParamField>

<ParamField body="Field size" param-type="string" required="false" deprecated="false" show-location="false" enum="Regular,Large">
  For text fields, chooses **Regular** (single-line) or **Large** (bigger multi-line box). This is display size, not a character limit. The same **Field Size** control appears when you edit the field as a form question, and changing it there updates the profile field and every form that uses it.
</ParamField>

<ParamField body="Default question text" param-type="string" required="false" deprecated="false" show-location="false">
  Sets the prompt shown when the field appears on forms or other entry screens.
</ParamField>

<ParamField body="Default formatting" param-type="string" required="false" deprecated="false" show-location="false">
  Applies formatting expectations such as phone or email when supported.
</ParamField>

<ParamField body="Include on health report" param-type="boolean" required="false" deprecated="false" show-location="false">
  Adds the field to the health report when selected.
</ParamField>

<ParamField body="Who has access" param-type="string" required="false" deprecated="false" show-location="false">
  Limits field visibility by role. If left empty, all CampiumDB users can see the field data.
</ParamField>

<ParamField body="Description" param-type="string" required="false" deprecated="false" show-location="false">
  An internal-only note that helps staff understand the field's purpose.
</ParamField>

After you save, the field appears in the Profile Fields table.

<Callout kind="info" collapsed="false">
  If you create a **Choose One**, **Choose Many**, or **Ranked Choice** field, the field is not ready for use until you add options.
</Callout>

## Family fields

Use **Family** when everyone in the household should share one answer (for example, a shared doctor name or emergency note).

1. Open **Admin → Profile Fields**.
2. Create a field or open **Edit Profile Field**.
3. Under **This field will be used for**, choose **Family**.
4. Save. Only **Text**, **Date**, and multiple-choice types (**Choose One** / **Choose Many**) can be Family fields. Other types show: **Only text, date and multiple choice fields can be shared by a family.**

On profiles, a **Family** badge (title **Shared by the whole family**) marks the field. Editing the answer on any member updates it for the whole family. Forms that include the field save to that same shared answer.

If the field already has answers and you try to switch between Person and Family, Campium blocks the change for regular staff: **This field already has answers, so it can't switch between Person and Family here. Contact Campium support to convert it.** New Family fields, or eligible fields with no answers yet, can still be set to **Family** from the editor.

## Linked Fields

**Linked Fields** lets one **Choose One** dropdown update another when someone picks an option. Example: choosing a Group can fill in the matching Section.

1. Open **Admin → Profile Fields**.
2. Click **Linked Fields** (toolbar button on the main list).
3. Click **Link two fields**.
4. Under **When this field changes**, choose the source. Under **Update this field**, choose the target. Both must be single-choice (**Choose One**) dropdowns. Click **Continue**.
5. For each source option, pick the matching target option (or leave unmapped so the target stays as-is when that source option is chosen). Clearing the source clears the target. The mapping table includes a **Saving updates** column that counts who would change.
6. As you map options, a live preview shows **Checking who this would update...**, then **Saving updates** with the target field name and person count (or **Saving updates no one.**), with move counts such as `3 from blank to Section A`. Use **Show names** / **Hide names** to list sample people. Helper text: **Only active and pending profiles are updated. Inactive profiles keep what they have.** People in options you did not change who already differ can be left alone, or you can choose **Update them**.
7. Click **Link fields** (or **Save** when editing). Confirm with a prompt that names how many people will be updated (or **Save this link? No one is updated.**). Confirm button: **Yes, save it**. If people need updating, a progress dialog shows counts for **Updated**, **Skipped**, and **Failed**, plus **Close** and a retry control when needed.

On the Linked Fields list, use **Edit** or **Remove** on an existing link, or **Back to Linked Fields** from the mapping screen.

Rules:

- A field cannot link to itself, be both a source and a target, or have more than one source.
- You need **Profile Fields** access (same permission as the rest of this page).
- Group and Section pairs that already use Group Settings keep those mappings; Linked Fields does not replace that special case.

## Ranked Choice fields

Use **Ranked Choice** when someone should put options in preference order, not only select them.

1. Open **Admin → Profile Fields** and create a field (or open an existing Ranked Choice field).
2. Set **Type of Field** to **Ranked Choice**.
3. Under **How many can they rank?**, set **At least** and **Up to**.
4. Open **Options** from the row menu and add the choices people can rank.
5. Put the field on a form like any other profile field.

On the parent portal and registration forms, families see one dropdown per rank slot (1st choice, 2nd choice, and so on). Answers save in rank order and show that way on profiles, reports, and exports.

<Callout kind="info" collapsed="false">
  You cannot change an existing field into or out of **Ranked Choice**. Create a new Ranked Choice field instead of converting a Choose Many field (or the reverse), so older answers are not treated as ranked when they never were.
</Callout>

<Callout kind="info" collapsed="false">
  The Campium mobile app still treats Ranked Choice questions like **Choose Many** until a future app update. Families ranking on the web portal or admin forms see the ranked slots.
</Callout>

## Manage options for choice fields

Choose One, Choose Many, and Ranked Choice fields depend on an option list. After creating the field, open **Options** from the row menu to define the choices people can select.

### What you can do in Options

- **Add options** by entering a value and pressing Enter after each one

- **Reorder options** by dragging them into the order you want

- **Sort options** alphabetically or numerically with the available sort tools

- **Edit options** when a label needs to change

- **Hide from parent portal** / **Show on parent portal** from the option's ⋮ menu, so families no longer see a choice (or see it again) without deleting it

- **Merge options** when two choices should become one

- **Delete options** that you no longer need

Campium shows a badge count for each option so you can see how many records currently use it. That count helps you judge the impact before editing, merging, or deleting an option.

### Hide an option from profile dropdowns

Use this when a choice should stop appearing on the parent portal, registration forms, and admin profile pickers, but you still need the option on the Options list for history.

1. Open **Options** for the field.
2. Open the option's ⋮ menu and select **Hide from parent portal**.
3. Confirm with **Yes, Hide it**. Campium explains that existing answers are kept; parents see a blank field and need to pick another option if the question is required.
4. The option stays in your Options list with an **Inactive** badge.

Hidden options no longer appear in admin profile dropdowns either (including when someone already had that answer selected). The next time that profile is saved, the hidden answer is cleared, so pick a current option first if you still need a value. The Options list itself still shows the choice with **Inactive**.

To bring it back, open the same menu and select **Show on parent portal**, then confirm with **Yes, Show it**.

This is separate from setting the whole field to **Active** or **Inactive**.

<Callout kind="info" collapsed="false">
  Primary and system fields can include locked options. Locked options cannot be edited the same way as custom field options.
</Callout>

## Edit a field without losing data

Use **Edit** from the row menu to update an existing field's settings. You can rename the field, change user types, adjust size, update question text, change formatting, toggle the health report setting, and revise role access.

You can also change the field status between **Active** and **Inactive**. Inactive fields are hidden from normal use, but Campium keeps the existing answers.

### Active vs. inactive

Set a field to inactive when you want to stop using it without removing historical data. This is the safest option when the field has been used on profiles, forms, or reports and you may need those answers later.

Some core or system-managed fields are more restricted. Depending on the field, Campium may prevent renaming or deleting it.

## Know where answers appear

A single profile field can appear in several places across Campium. You define the field once, and answers can be collected, displayed, or reported in multiple workflows.

Profile field answers can appear in:

- **Admin profiles** on tabs and layouts

- **Registration forms**

- **Parent Portal**

- **Reports** as optional extra columns

- **Health report**

- **Staff Hub**

This shared behavior is why the **Usage** action matters. Use **View Usage** before you edit or remove a field so you can see where that field is currently referenced.

## Control access and visibility

Field access is controlled on the field itself. This role-based access is separate from the broader page permissions configured in Roles and Permissions.

By default, all CampiumDB users can see all profile field data. Restrict access on sensitive fields when only certain roles should view or work with that information.

Use **Access Rights** on a field (or **Who has access?** when you create or edit the field) to choose which staff roles can see that field's answers. Profile search and autocomplete also respect those grants, so staff only see matching answers for fields their role can access. Changes apply right away.

<Callout kind="info" collapsed="false">
  Page access controls whether someone can open Profile Fields. Field access controls whether they can see the data in a specific field, including in search results.
</Callout>

## Copy, delete, or clear answers

The row menu includes several maintenance actions for existing fields.

| Action                         | What it does               | Important detail                                       |
| ------------------------------ | -------------------------- | ------------------------------------------------------ |
| **Copy Field**                 | Duplicates the field setup | Copies the field configuration only, not saved answers |
| **Delete Profile Field**       | Removes the field          | Campium blocks deletion if the field is in use         |
| **Remove Everyone's Response** | Clears saved answers       | The field remains in place and can still be used again |

System and primary fields cannot be deleted. If you need to stop using one of these fields, set it to inactive instead when that option is available.

### Clear answers with Remove Everyone's Response

Use **Remove Everyone's Response** when you want to wipe answers for a field without deleting the field itself. This is common at season change when parents should answer again.

1. Open **Admin → Profile Fields**.
2. Open the row menu (⋮) for the field and select **Remove Everyone's Response**.
3. In the **Remove responses** dialog, choose a scope:
   - **All responses** removes every saved answer for that field.
   - **Only responses last updated before:** removes answers whose last update is before the date you pick. Newer answers stay. Pick a date that is today or earlier.
4. Select **Remove responses** to confirm.

Campium shows how many answers were removed (for example, **Removed 42 responses.**). This cannot be undone, so prefer the date scope when some families have already answered for the new season.

<Callout kind="info" collapsed="false">
  Last updated uses the answer's last update time, or its created time when no update time is stored. Answers with neither date are kept when you use a date cutoff.
</Callout>

## Use Profile Layouts to place fields on profiles

Creating a field does not automatically place it on every profile tab. **Profile Layouts** is a separate Admin area that controls where fields appear on profiles, how tabs are organized, and what order fields use for each user type.

### Address fields stay together in pickers

Street, line 2, city, state, and zip that belong to the same address stay grouped in field pickers (reports, column choosers, All User Data, bunk labels, and similar lists). City, state, and zip sit directly under their street field instead of sorting alphabetically across the whole list. Custom Profile Layouts that you arrange by hand are not regrouped.

The usual flow is:

**Profile Fields** → **Profile Layouts** → **Forms and reports**

Create the field first, then place it where staff should see it.

## Practical tips for managing fields

<Callout kind="tip" collapsed="false">
  - Use **Description** for internal notes so staff know why a field exists.

  - Mark medical or safety-related fields for the **health report** when staff need quick access.

  - Use **Inactive** instead of delete when you want to preserve history.

  - Check **View Usage** before editing or removing a field that may appear in multiple places.

  - Add options immediately after creating **Choose One** or **Choose Many** fields so the field is usable.
</Callout>

## Follow the full setup flow

<Steps>
  <Step title="Define the field" icon="plus" title-type="p">
    Create the field in **Admin → Profile Fields** and choose its name, type, and user type. After you save, the field appears in the searchable table.
  </Step>

  <Step title="Add options if the field uses choices" icon="edit" title-type="p">
    If the field type is **Choose One** or **Choose Many**, open **Options** and add the answer choices. When options are in place, the field is ready to collect valid answers.
  </Step>

  <Step title="Set access and reporting behavior" icon="shield" title-type="p">
    Review who can see the field, whether it belongs on the health report, and any default question text or formatting. This is the point where you decide who uses the field and how sensitive it is.
  </Step>

  <Step title="Place the field on profile layouts" icon="settings" title-type="p">
    Open **Profile Layouts** and add the field to the right profile tab and position for the relevant user type. Once it is placed, staff can find it where they expect it on the profile.
  </Step>

  <Step title="Use the field in forms, reports, and Staff Hub" icon="book-open" title-type="p">
    After setup, the same field can be reused across registration forms, the parent portal, reports, the health report, and Staff Hub. One field definition supports many workflows.
  </Step>

  <Step title="Collect and update answers" icon="check-circle" title-type="p">
    Answers normally save on each person's record. **Family** fields keep one shared answer for the household. Staff can update answers later from the profile or through forms, depending on where the field is exposed.
  </Step>
</Steps>

## Keep your field setup maintainable

Profile fields work best when names are clear, access is intentional, and layouts match how staff actually use the data. Review field usage before making major changes, especially for fields tied to reports, forms, or health workflows.

When you need to retire a field, inactivating it usually gives you a cleaner result than deleting it. You keep historical answers, avoid breaking downstream usage, and leave yourself a clear record of how the field was used.
