title: Test Mode
description: Preview forms on the parent portal before launch using Test Mode, including who can see it and how to test safely.

Test Mode lets staff open a form on the parent portal before the form's open window. While it is on, the form shows for everyone of its user type from a staff login, whatever your recipient filters say. Use it to check the form experience and catch issues before launch.

You can turn on Test Mode from **Forms** in the left navigation, then open the form and use the **TEST MODE** toggle in the form toolbar. You can also use the **Test Mode** toggle next to the availability chip on the **Forms** step in **Guided setup**.

Helper text beside the switch: **In test mode, this form shows for everyone of its user type, whatever your recipient filters, and only from a staff login. Turns off once the form opens.** Use **Check a person** to confirm whether a specific account can see it.

<Callout kind="info" collapsed="false">
Test Mode does **not** open the form to family-only logins. Staff must sign in with a staff login on the parent portal. It also ignores the form's **Recipients** filters while it is on, so every staff login of that user type can open it for testing.
</Callout>

## Who can use Test Mode

Only people who are signed into the **parent portal** with a staff or admin role can see a Test Mode form. Regular family accounts still follow the form's normal visibility rules and do not get Test Mode access.

| Person | Can use Test Mode? | What happens |
| --- | --- | --- |
| Staff or admin user signed into the parent portal | Yes | Can view the form before it opens, for that form's user type |
| Family-only login | No | Does not get Test Mode access |

A red **Test Mode** badge appears on the admin Forms list and next to the form on the portal while Test Mode is active.

## What Test Mode changes

Test Mode lets staff open the form before its open window. It does not change every form setting.

### What Test Mode allows

| Setting or rule | In Test Mode | Notes |
| --- | --- | --- |
| Before the Start Date | Allowed for staff | Staff of that user type can open the form |
| After the End Date | Allowed for staff | Same as above while Test Mode is still on |
| Recipients filters | Bypassed | Everyone of the form's user type can open it from a staff login |
| Staff login on the parent portal | Required | Family-only logins do not get Test Mode |

### What Test Mode does not bypass

| Setting or rule | Bypassed in Test Mode? | Notes |
| --- | --- | --- |
| Visibility set to Hidden | No | Hidden forms stay hidden |
| Family access rules | No | Families do not get Test Mode access |
| Form content | No | Test Mode does not change fields, logic, or form behavior |

## Submit - test mode at checkout

When Test Mode is on and you are signed into the parent portal with a staff or admin login, checkout can offer **Submit - test mode** ($0.00). Description: **Test mode only. Nothing is charged and no card is needed.** Membership checkout also shows **How much today?** so you can pick that option instead of paying in full.

The receipt warns that the enrollment is real even though no card was charged. Remove those enrollments before families register for real.

## Test enrollments

When staff check out with **Submit - test mode** (or another $0 checkout on a Test Mode form), Campium keeps those enrollments on the form so you can clear them before families register.

Open the form's **Settings** and use the **Test enrollments (N)** chip:

- Review who enrolled in test mode.
- **Remove** one person, or **Remove all**.
- Turning Test Mode off while enrollments remain warns you to remove them from **Test enrollments** on the form's settings before families register. The form-opening digest can also note how many are left to remove.

A card charge made on a Test Mode form is real money and is not listed under **Test enrollments**.

## Safe testing checklist

<Steps>
  <Step title="Confirm Visibility" icon="eye">
  Make sure **Visibility** is not **Hidden** if you need staff to open the form through Test Mode.

  If you set **Visibility** to **Hidden**, staff also will not be able to open it through Test Mode.
  </Step>

  <Step title="Turn on Test Mode in the form toolbar" icon="settings">
  Go to **Forms**, open the form, and switch on **TEST MODE**. Or open **Guided setup**, go to the **Forms** step, and switch on **Test Mode**. Use **Check a person** if you are unsure who can see it.

  Check for the red **Test Mode** badge so you know Test Mode is active.
  </Step>

  <Step title="Sign into the parent portal as staff" icon="user">
  Open the parent portal with a staff or admin login. Family-only accounts will not see the Test Mode form.
  </Step>

  <Step title="Walk the form" icon="check-circle">
  Complete the form as a tester. Prefer **Submit - test mode** when you want a $0 checkout with no card. Remove any **Test enrollments** before you open the form to families.
  </Step>
</Steps>

## What staff and families see

Test Mode creates a different experience for staff admins than for families.

| Viewer | If Test Mode is on | What they see |
| --- | --- | --- |
| Staff or admin on the parent portal | Can open the form before its live window | Sees the form from a staff login for that user type |
| Family-only login | No Test Mode access to this form | Does not see the form until it is open for real |

If a form is already visible, active, within its dates, and matches the right recipients, families can still see it during your testing period. Test Mode does not block family access by itself.

## When Test Mode turns off

Test Mode turns off automatically when the form goes live. This happens when the form is visible, active, and the current date falls between the Start Date and End Date.

While the form stays in that open window, you cannot turn Test Mode back on from Guided setup (the switch is locked). On the form editor, the **TEST MODE** tooltip also notes that Test Mode turns off automatically while the form is open. Clicking the locked switch can show: **Test mode is off because this form is open. Families can already see it on the portal.**

If Test Mode switches off on its own, that usually means the form has entered its live window. This is expected behavior, not an error.

## Troubleshooting

### Staff cannot see the form in Test Mode

- Confirm **TEST MODE** / **Test Mode** is still on
- Confirm the person is signed into the parent portal with a staff or admin login
- Confirm **Visibility** is not **Hidden**
- Confirm the form's user type matches who you are testing as

### Test Mode switched off by itself

This usually means the form became live. When the form is visible, active, and in its date range, Test Mode turns off automatically.

### Test Mode switch is not visible

- reopen the form from **Forms**
- or open **Guided setup → Forms**

## Test Mode vs. other settings

| Setting | What it does | Softened in Test Mode? | Still required? |
| --- | --- | --- | --- |
| Test Mode | Lets staff open the form before it opens | Yes | No |
| Visibility | Whether the form can appear at all | No | Yes |
| Start Date and End Date | When the form is live | Softened for staff while Test Mode is on | Yes |
| Recipients | Which users the form is assigned to when live | Bypassed while Test Mode is on | Yes when live |
| Submit - test mode | Staff $0 checkout with no card on a Test Mode form | Yes (staff only) | No |

## After testing

1. Remove any leftover **Test enrollments**.
2. Confirm Recipients, questions, and products are ready for launch.
3. Turn **TEST MODE** off if the form is not yet open (or wait for the open window to turn it off).
4. Confirm the red **Test Mode** badge is gone once the form is live.
