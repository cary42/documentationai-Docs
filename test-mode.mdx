## Preview a form before families can access it

Test Mode lets staff open a form on the parent portal before the form's open window. Only the form's recipients can see it, and only from a staff login. Use it to check the form experience, confirm the right account or camper can see it, and catch issues before launch.

You can turn on Test Mode from **Forms** in the left navigation, then open the form and use the **TEST MODE** toggle in the form toolbar. You can also use the **Test Mode** toggle next to the availability chip on the **Forms** step in **Guided setup**.

Helper text beside the switch: **In test mode, only your recipients see this form (N), and only from a staff login. Turns off once the form opens.** Use **Check a person** to confirm whether a specific account is in that recipient list.

<Callout kind="info">

Test Mode does **not** open the form to every staff login. It stays limited to the people on the form's **Recipients** list (or the audience rules you set), and those people must sign in with a staff login on the parent portal.

</Callout>

## Who can use Test Mode

Only people who are signed into the **parent portal** with a staff or admin role, and who are on the form's recipient list, can see a Test Mode form. Regular family accounts still follow the form's normal visibility rules and do not get Test Mode access.

| Person | Can use Test Mode? | What happens |
| --- | --- | --- |
| Staff or admin user signed into the parent portal who is on the form's recipients | Yes | Can view the form before it opens |
| Staff or admin user who is not on the recipients list | No | Does not see the form in Test Mode |
| Family account | No | Sees the form only when normal visibility, date, and recipient rules allow it |
| Staff or admin user not signed into the parent portal | No | Cannot preview the form on the portal until they log in there |

A red **Test Mode** badge appears on the admin Forms list and next to the form on the portal while Test Mode is active.

## Where to find Test Mode

You can reach the toggle from the form editor or from Guided setup.

### From Forms

<Steps>
  <Step title="Open Forms" icon="folder">

  In Campium, go to **Forms** in the left navigation.

  </Step>
  <Step title="Open the form you want to test" icon="edit">

  Select the form you want to preview before launch.

  </Step>
  <Step title="Turn on TEST MODE" icon="play-circle">

  Use the **TEST MODE** toggle in the form toolbar.

  After you turn it on, look for the red **Test Mode** badge on the Forms list and on the parent portal next to the form.

  </Step>
</Steps>

### From Guided setup

<Steps>
  <Step title="Open Guided setup" icon="folder">

  Go to **Seasons**, then click the season name (or **Guided setup** on the row). See [Guided Season Setup](/guided-season-setup).

  </Step>
  <Step title="Open the Form step" icon="edit">

  Move to the **Form** step and choose the form you want to preview.

  </Step>
  <Step title="Turn on Test Mode" icon="play-circle">

  Use the **Test Mode** toggle next to the form availability chip in the Forms toolbar.

  The helper explains that only your recipients see the form from a staff login, and that Test Mode turns off once the form opens. While the form is already **Open**, the switch is locked off.

  </Step>
</Steps>

## What Test Mode changes

Test Mode lets recipient staff open the form before its open window. It does not change every form setting.

### What Test Mode allows

| Setting or rule | In Test Mode | Notes |
| --- | --- | --- |
| Before the Start Date | Allowed for recipient staff | Staff on the recipient list can open the form |
| After the End Date | Allowed for recipient staff | Same as above while Test Mode is still on |
| Recipients list | Still enforced | Only recipients see the form |
| Staff login on the parent portal | Required | Family-only logins do not get Test Mode |

### What Test Mode does not bypass

| Setting or rule | Bypassed in Test Mode? | Notes |
| --- | --- | --- |
| Visibility set to Hidden | No | Hidden forms stay hidden |
| Family access rules | No | Families do not get Test Mode access |
| Payment processing | No | Charges are real unless your payment processor is in sandbox mode |
| Form content | No | Test Mode does not change fields, logic, or form behavior |

<Callout kind="alert">

Submissions made during testing are **real submissions**. They appear in **Responses** and can trigger real emails, status changes, and payments. Payments are real unless your payment processor is in sandbox mode.

</Callout>

## How to test a form

Use this workflow to preview safely and avoid accidental family access.

<Steps>
  <Step title="Confirm the form is limited to staff testing" icon="shield">

  Before you test, make sure families cannot see the form unless you want them to.

  Good ways to keep testing staff-only include:

  - Set the form to start in the future
  - Narrow the Recipients list
  - Set visibility carefully based on your testing plan

  If you set **Visibility** to **Hidden**, staff also will not be able to open it through Test Mode.

  </Step>
  <Step title="Turn on Test Mode in the form toolbar" icon="settings">

  Go to **Forms**, open the form, and switch on **TEST MODE**. Or open **Guided setup**, go to the **Forms** step, and switch on **Test Mode**. Confirm the recipient count in the helper text, and use **Check a person** if you are unsure who is included.

  Check for the red **Test Mode** badge so you know Test Mode is active.

  </Step>
  <Step title="Sign into the parent portal with a staff or admin account" icon="users">

  Open the parent portal using a login that has both:

  - access to the parent portal
  - a staff or admin role in Campium

  A regular family login will not show the form unless the normal rules already allow it.

  </Step>
  <Step title="Open the correct account or camper view" icon="check-circle">

  Make sure you are viewing the same camper or account context the form is meant for.

  If the form is tied to a different recipient, account, or organization context, the portal view can still be different from what you expect.

  </Step>
  <Step title="Submit only if you want to test the full workflow" icon="alert-triangle">

  Submit the form only when you are ready to create a real response.

  A successful test submission appears in **Responses** and may send emails, change statuses, or process payment.

  </Step>
</Steps>

## What families see vs. what staff see

Test Mode creates a different experience for staff admins than for families.

| Viewer | If Test Mode is on | What they see |
| --- | --- | --- |
| Staff or admin on the parent portal who is on the Recipients list | Can open the form before its live window | Sees the form from a staff login |
| Staff or admin who is not on the Recipients list | No Test Mode access to this form | Does not see the form |
| Family user | Follows normal form rules | Sees the form only if it is visible, active, in date range, and matches recipients |
| Staff or admin outside the parent portal | No portal preview access | Must sign into the parent portal to test the form there |

If a form is already visible, active, within its dates, and matches the right recipients, families can still see it during your testing period. Test Mode does not block family access by itself. It also does not let staff skip the Recipients list.

## Automatic turn-off

Test Mode turns off automatically when the form goes live. This happens when the form is visible, active, and the current date falls between the Start Date and End Date.

While the form stays in that open window, you cannot turn Test Mode back on from Guided setup (the switch is locked). On the form editor, the **TEST MODE** tooltip also notes that Test Mode turns off automatically while the form is open.

If Test Mode switches off on its own, that usually means the form has entered its live window. This is expected behavior, not an error.

## Troubleshooting

### Form is not visible on the portal

Check these items first:

- Make sure you are signed into the **parent portal**, not only the admin side
- Confirm your login has a **staff or admin role**
- Make sure you are viewing the correct camper or account
- Confirm the form belongs to the same organization or subdomain you are testing
- Check that **Test Mode** is still turned on

### Families can see the form during testing

Families can see the form if the form is already:

- visible
- inside its start and end dates
- available to matching recipients

If you want staff-only testing, use one of these options:

- set the Start Date in the future
- narrow the Recipients list
- keep the form out of its normal live conditions

### Test Mode switched off by itself

This usually means the form became live. When the form is visible, active, and in its date range, Test Mode turns off automatically.

### Test Mode switch is not visible

Try these steps:

- refresh the page
- reopen the form from **Forms**
- confirm you have permission to edit the form

## Test Mode vs. other settings

Use this table to understand what each setting controls.

| Setting | What it controls | Affects staff testing? | Affects families? |
| --- | --- | --- | --- |
| Test Mode | Lets recipient staff open the form before it opens | Yes | No |
| Visibility | Whether the form is shown at all | Yes (Hidden stays hidden) | Yes |
| Start Date and End Date | When the form is live | Softened for recipient staff while Test Mode is on | Yes |
| Recipients | Which users the form is assigned to | Still required in Test Mode | Yes |
| Payment processor mode | Whether charges are test or live | Yes | Yes |

## Quick checklist before going live

1. Turn off any staff-only testing setup you added for previewing.
2. Confirm the form is **Visible** if families should be able to access it.
3. Check the **Start Date** and **End Date**.
4. Review the **Recipients** list.
5. Submit a final test only if you are comfortable creating a real response.
6. Verify any payment settings, especially if you do not want live charges.
7. Confirm the red **Test Mode** badge is gone once the form is live.
