## What you can do with Discounts

Use the Discounts page in Campium Admin to manage discount codes, sibling discounts, and multi-session discount settings for your programs. Discounts control how much families save, when they qualify, and whether staff or families can apply them at checkout.

Use this page when you want to:

- Create new discount codes for promotions or financial aid
- Create a **Sibling discount** that applies automatically when a family registers two or more children
- Edit, archive, or delete existing discounts
- Control when and where a discount can be used
- Set up multi-session discounts that reward additional registrations
- Let a discount cover the full checkout amount so families do not need to pay anything at checkout

<Callout kind="info" collapsed="false">
  Discounts affect how much families pay at checkout. Make changes only if you understand your pricing policies and how they appear on invoices.
</Callout>

## Open the Discounts page

<Steps>
  <Step title="Open the Admin menu" icon="settings" title-type="p">
    From the left sidebar, click **Admin**.
  </Step>

  <Step title="Go to Discounts" icon="settings" title-type="p">
    In the Admin menu, click **Discounts**.
  </Step>
</Steps>

When the page loads, you see a list of discounts and any multi-session discount configurations available to your account.

## Discount list: columns and status

Each row in the discount list represents one discount. Use the columns to understand how each discount behaves.

<ParamField body="code" param-type="string" required="false" deprecated="false" show-location="false">
  **Code** — The code families or staff enter at checkout. Sibling discounts show a **Sibling** badge next to the code.
</ParamField>

<ParamField body="description" param-type="string" required="false" deprecated="false" show-location="false">
  **Description** — The text that appears on invoices and receipts. Use wording that families will recognize.
</ParamField>

<ParamField body="status" param-type="string" required="false" deprecated="false" show-location="false">
  **Status** — Shows whether the discount can currently be used. Typical values include:

  - **In use**: Discount is active and can be applied when other conditions are met.
  - **Not in use**: Discount is disabled or blocked by another setting.
  - **Expired**: Discount is past its end date.
</ParamField>

<ParamField body="amount" param-type="number" required="false" deprecated="false" show-location="false">
  **Amount** — Shows either a fixed dollar amount or a percentage discount, depending on how the discount was set up.
</ParamField>

<ParamField body="public" param-type="boolean" required="false" deprecated="false" show-location="false">
  **Public?** — Shows whether families can use the code in the parent portal:

  - **Yes**: Parents can enter this code at checkout.
  - **No**: Only staff can apply it from Admin.
</ParamField>

<ParamField body="allowDuplicates" param-type="boolean" required="false" deprecated="false" show-location="false">
  **Allow duplicates?** — Controls whether the same family can receive the discount more than once:

  - **Yes**: The same user can use this discount multiple times.
  - **No**: The user can only receive this discount once.
</ParamField>

<ParamField body="usage" param-type="integer" required="false" deprecated="false" show-location="false">
  **Usage** — How many times the discount has been used.
</ParamField>

<ParamField body="limit" param-type="integer" required="false" deprecated="false" show-location="false">
  **Limit** — Maximum number of allowed uses, if you set one. Blank or zero means no limit.
</ParamField>

<ParamField body="startEndDate" param-type="string" required="false" deprecated="false" show-location="false">
  **Start Date / End Date** — The date range when the discount is valid. Outside this window, the discount cannot be applied.
</ParamField>

Use the action menu on each row to edit, archive, or delete a discount.

## Create a new discount

Create a new discount when you want to launch a promotion, offer financial aid, apply staff-only adjustments, offer a pay in full discount, make checkout free for the family, or set up an automatic sibling discount.

<Steps>
  <Step title="Start a new discount" icon="plus" title-type="p">
    Click **Add New Discount** on the Discounts page.
  </Step>

  <Step title="Choose the discount type" icon="settings" title-type="p">
    Under **Discount Type**, choose:

    - **Code discount**: families type a code at checkout (or staff apply it in Admin).
    - **Sibling discount**: applied automatically when a family registers two or more children. Every child except the highest-priced one receives it.

    You can have only one sibling discount. If one already exists, **Sibling discount** is disabled and you see a link to **Edit it**.
  </Step>

  <Step title="Enter code and description" icon="edit" title-type="p">
    For a **Code discount**:

    - Fill in **Discount Code**. This is what families or staff enter at checkout.
    - Fill in **Discount Description**. This appears on invoices and receipts.

    For a **Sibling discount**, the code field is hidden. Description defaults to **Sibling Discount** if you leave it blank.
  </Step>

  <Step title="Set the discount value" icon="edit" title-type="p">
    Enter either:

    - **Fixed Amount** (for example, `25.00` for a twenty-five dollar discount), or
    - **Percent** (for example, `10` for ten percent off)

    Leave the other field at zero. Only one value can be used at a time.
  </Step>

  <Step title="Optionally limit total uses" icon="settings" title-type="p">
    For a **Code discount**, in **Limit**, enter the maximum number of times this discount can be used.\
    Leave blank or enter `0` for no limit. Sibling discounts do not use Limit.
  </Step>

  <Step title="Choose how a percent discount applies across sessions" icon="settings" title-type="p">
    Set **Apply To All Sessions**:

    - **Yes**: A percent discount applies to every eligible session for that child.
    - **No**: A percent discount applies only to the child's lowest-priced session.
  </Step>

  <Step title="Choose how sessions are counted across children" icon="settings" title-type="p">
    For a **Code discount**, set **Combine All Children's Sessions** to control how a percent discount is calculated when a family has more than one child:

    - **Yes**: The discount is computed across all children's sessions combined.
    - **No**: The discount is computed separately for each child.

    Sibling discounts hide this setting and always calculate per child (not combined across the cart).
  </Step>

  <Step title="Configure a pay in full discount" icon="check-circle" title-type="p">
    Use a pay in full discount when you want to reward families who pay the full balance up front instead of choosing installments, or when you want checkout to be free for the family.

    Set the discount amount as either a **Fixed Amount** or **Percent**, then make sure the discount is visible where families check out if you want them to apply it themselves.

    Some discounts can also be set to skip payment completely by turning on **Bypass payment at portal checkout?**. When this setting is turned on, parents can submit their registration without entering a card or ACH payment, so the family does not need to pay anything at checkout.

    To make the discount work as expected:

    - Set **Allow On Portal?** to **Yes** if families should apply it in the parent portal.
    - Set **Start Date** and **End Date** if the discount should only apply during a specific registration window.
    - Set **Limit** if you want to cap how many pay in full discounts can be used.
    - Use **Apply Only To These Products** to control which registrations qualify.
  </Step>

  <Step title="Control who can use the discount" icon="users" title-type="p">
    For a **Code discount**, set **Allow On Portal?**:

    - **Yes**: Families can enter the code during checkout in the parent portal.
    - **No**: Only staff can apply the discount in Admin.

    Sibling discounts always apply on the portal automatically, so this setting is hidden.
  </Step>

  <Step title="Control repeat usage" icon="settings" title-type="p">
    For a **Code discount**, set **Allow Duplicate?**:

    - **Yes**: The same user can receive the discount multiple times.
    - **No**: The discount applies at most once per user.

    Sibling discounts hide this setting.
  </Step>

  <Step title="Choose calculation order" icon="settings" title-type="p">
    Set **Apply After Other Discounts?**:

    - **Yes**: Calculate this discount after other discounts.
    - **No**: Use standard calculation order with other discounts.
  </Step>

  <Step title="Add optional date window" icon="calendar" title-type="p">
    Optionally set **Start Date** and **End Date** to control when the discount is active.\
    Leave these blank to allow use at any time (subject to other settings).
  </Step>

  <Step title="Target specific products (optional)" icon="package" title-type="p">
    In **Apply Only To These Products**, select the products the discount should apply to.\
    Leave this blank to allow the discount to apply across all eligible products.
  </Step>

  <Step title="Save the discount" icon="check-circle" title-type="p">
    Review your entries and click **Save**.\
    If the save succeeds, the discount appears in the list with the updated settings.
  </Step>
</Steps>

<Callout kind="tip" collapsed="false">
  Test new discounts with a sample registration before promoting them to families. Confirm the discount amount, visibility, and invoice description match your expectations. For sibling discounts, register two or more children in one checkout and confirm every child except the highest-priced one receives the discount.
</Callout>

## Create a sibling discount

A **Sibling discount** applies automatically at checkout when a family registers two or more children. Every child except the highest-priced one receives it. Families do not type a code.

<Steps>
  <Step title="Open Add New Discount" icon="plus" title-type="p">
    Go to **Admin → Discounts** and click **Add New Discount**.
  </Step>

  <Step title="Select Sibling discount" icon="users" title-type="p">
    Under **Discount Type**, choose **Sibling discount**. The explainer confirms it applies when a family registers two or more children.
  </Step>

  <Step title="Set amount or percent and description" icon="edit" title-type="p">
    Enter a **Fixed Amount** or **Percent**, and confirm **Discount Description** (defaults to **Sibling Discount** if blank).
  </Step>

  <Step title="Set remaining rules and save" icon="check-circle" title-type="p">
    Set **Apply To All Sessions**, **Apply After Other Discounts?**, dates, and product restrictions as needed, then click **Save**.

    Code-only fields (**Discount Code**, **Combine All Children's Sessions**, **Allow On Portal?**, **Bypass payment at portal checkout?**, **Allow Duplicate?**, and **Limit**) stay hidden for sibling discounts.
  </Step>
</Steps>

If you already have a sibling discount, create flow disables **Sibling discount** and links you to edit the existing one. On the discount list, sibling rows show a **Sibling** badge. When you edit a sibling discount, **Discount Type** shows **Sibling Discount** instead of a code field.

## Edit, archive, or delete a discount

Use the action menu on each discount row to update or remove a discount.

<Steps>
  <Step title="Open the action menu" icon="settings" title-type="p">
    In the discount list, click the action menu for the discount you want to change.
  </Step>

  <Step title="Edit a discount" icon="edit" title-type="p">
    Choose **Edit Discount** to update fields like amount, dates, or description.\
    Adjust the fields, then click **Save**. Changes affect new uses of the discount.
  </Step>

  <Step title="Archive a discount" icon="archive" title-type="p">
    Choose **Archive Discount** when you want to stop using a discount but keep its history.\
    Archived discounts move out of the active list and no longer apply to new checkouts.
  </Step>

  <Step title="Delete a discount" icon="trash" title-type="p">
    Choose **Delete Discount** to permanently remove the discount from your account.\
    Confirm the deletion when prompted. **Delete** is only available for a discount that has never been used; a discount that has already been applied shows no **Delete Discount** option, so archive it instead.
  </Step>
</Steps>

<Callout kind="alert" collapsed="false">
  Deleting a discount performs a hard delete in the database and cannot be undone. Because delete is only offered for a discount that has never been used, use **Archive** to stop using a discount that already has usage history.
</Callout>

## Key settings explained

### Public vs non-public discounts

Use public settings to control who can apply a discount.

- **Public = Yes**: Parents can enter the code themselves in the parent portal during checkout.
- **Public = No**: Staff must apply the discount from Admin; parents cannot see or use the code.

Public discounts work well for general promotions. Non-public discounts work better for case-by-case adjustments or internal programs.

### Limit (capacity)

Limit controls how many times a discount can be used across all families.

- **Blank or 0**: No usage cap. The discount can be used indefinitely, subject to date range and other rules.
- **Any positive number**: The discount stops working after it reaches that many successful uses.

Use limits for early-bird specials, limited-seat promotions, or grants with fixed budgets.

### Date range

Start and end dates control when a discount is active.

- If you set a **Start Date**, the code cannot be used before that date.
- If you set an **End Date**, the code stops working after that date.
- If you leave both blank, the discount stays active unless you archive or delete it, or it hits a usage limit.

When a discount is outside its date range, families and staff see validation errors and the discount will not apply.

### Product restriction

Product restrictions control where a discount applies.

- If you select one or more products in **Apply Only To These Products**, the discount applies only to those products.
- If you leave this blank, the discount can apply broadly across eligible products and forms.

Use product restrictions to limit discounts to certain camps, add-ons, or seasons.

### Bypass payment at portal checkout

Some discounts can skip payment at checkout instead of only reducing the price. When you turn on **Bypass payment at portal checkout?** on a discount, parents can submit their registration in the parent portal without entering a card or ACH payment, so they proceed without paying the upfront amount.

You can combine this setting with a dollar or percent credit. Payment is bypassed at checkout and the credit is applied to the balance. This is useful for scholarships, financial aid agreements, or promotions where you want to remove the upfront barrier without changing the overall tuition.

There is a single field for this behavior. **Bypass payment at portal checkout?** is the same setting sometimes referred to as skipping the deposit — there is no separate toggle.

## Discount Calculator

The Discount Calculator lets you preview exactly how a discount will apply at checkout before you save it. Pick real families and sessions, and the calculator runs the same pricing engine that checkout uses — including tiered pricing, sibling discounts, and multi-session tiers — to show you an itemized breakdown. Nothing is written to the database; the preview is read-only.

<Callout kind="info" collapsed="false">
  The calculator uses the real checkout calculation engine, so the amounts you see match what families will actually be charged. No sales, carts, or payment records are created during a preview.
</Callout>

<Steps>
  <Step title="Open the discount editor" icon="edit" title-type="p">
    Go to **Admin** > **Discounts** and click **Add New Discount** or edit an existing discount. The calculator is built into the editor form.
  </Step>

  <Step title="Enter your discount settings" icon="settings" title-type="p">
    Fill in the code, amount or percent, date range, product restrictions, and other settings as you normally would. The calculator uses whatever is currently in the form — you do not need to save first.
  </Step>

  <Step title="Add people to the preview" icon="users" title-type="p">
    In the calculator panel, search for real families by name or account number. Select up to 6 children and choose which sessions each one is enrolled in (up to 40 sessions per child). The calculator uses each person's real tiered pricing.
  </Step>

  <Step title="Review the preview" icon="calculator" title-type="p">
    Click **Preview** to see the results. For each child, you see their sessions with real prices, each discount line applied (including the discount you are editing, sibling discounts, and multi-session tier discounts), the total discount amount, and the net amount after discounts. An order-level total shows the combined savings across all children.
  </Step>

  <Step title="Check for warnings" icon="alert-triangle" title-type="p">
    The preview flags issues like a discount being outside its date range, a duplicate discount being skipped, or an archived discount that no longer applies. Address these before saving.
  </Step>

  <Step title="Adjust and re-preview" icon="refresh-cw" title-type="p">
    Change any settings in the form and run the preview again. The results update immediately so you can iterate until the discount behaves the way you want.
  </Step>

  <Step title="Save when satisfied" icon="check-circle" title-type="p">
    Once the preview matches your expectations, click **Save** to create or update the discount.
  </Step>
</Steps>

The calculator supports multi-product cart simulation, so you can preview discounts that target specific products or apply broadly across eligible sessions. Sibling discounts are included automatically when you add more than one child to the preview.

## Multi-session discounts

Multi-session discounts automatically reward a registrant who enrolls in multiple qualifying sessions. These rules work on top of your regular discounts and use existing discount codes as tiers.

### Access and permissions

Multi-session discount configurations are available to all admins who have access to the Discounts page. If you do not see the Multi-Session Discount Configurations section, confirm that your role includes the Admin module.

<Callout kind="info" collapsed="false">
  Multi-session configurations are global pricing rules. Limit access to staff who manage tuition policies and discounts across your organization.
</Callout>

### What a multi-session configuration includes

Each multi-session configuration defines a volume-based discount rule.

<ParamField body="name" param-type="string" required="false" deprecated="false" show-location="false">
  **Name** — Internal label for the rule, such as `Summer Session Volume Discount`.
</ParamField>

<ParamField body="form" param-type="string" required="false" deprecated="false" show-location="false">
  **Form (optional)** — Limits the rule to one registration form, or applies it to all forms when left blank.
</ParamField>

<ParamField body="minimumSessions" param-type="integer" required="false" deprecated="false" show-location="false">
  **Minimum Sessions** — Minimum number of qualifying sessions required before the rule can apply a discount.
</ParamField>

<ParamField body="enabled" param-type="boolean" required="false" deprecated="false" show-location="false">
  **Enabled** — Turns the rule on or off without deleting it. Disabled rules do not apply at checkout.
</ParamField>

<ParamField body="discountTiers" param-type="array" required="false" deprecated="false" show-location="false">
  **Discount Tiers** — One or more tier rows. Each tier sets:

  - A **Session Count** threshold.
  - A **Discount** chosen from your existing discount codes that applies when the threshold is met.
</ParamField>

### Before you build multi-session rules

Multi-session tiers use discount codes you have already created. Add the discount codes first on the main Discounts list, then choose those codes in your multi-session tiers.

This keeps invoice descriptions consistent and lets you reuse the same discount setup in more than one place.

### How tiers work

Tiers are based on session counts. The system checks how many qualifying sessions a registrant has and finds the best match among your tiers.

- When a registrant reaches a tier's **Session Count**, they qualify for that tier's discount.
- If multiple tiers qualify, the system uses the best match for that session count, usually the highest threshold they meet.

**Example**

- Tier for **2 sessions** → uses discount code `MULTI2`.
- Tier for **4 sessions** → uses discount code `MULTI4`.

If a registrant has 5 qualifying sessions, the 4-session tier applies.

### Create a multi-session configuration

Use these steps from the Multi-Session Discount Configurations section on the Discounts page.

<Steps>
  <Step title="Open multi-session configurations" icon="settings" title-type="p">
    Scroll to **Multi-Session Discount Configurations** on the Discounts page.\
    If you do not see this section, your account or role may not have access.
  </Step>

  <Step title="Start a new configuration" icon="plus" title-type="p">
    Click **Add Multi-Session Discount** to open the configuration form.
  </Step>

  <Step title="Name and scope the rule" icon="edit" title-type="p">
    - Enter a **Name** to identify the rule internally.
    - Optionally choose a **Form** to limit where the rule applies, or leave this blank to apply across forms where eligible.
  </Step>

  <Step title="Set minimum sessions" icon="settings" title-type="p">
    In **Minimum Sessions**, enter the minimum number of qualifying sessions required before any tier can apply.\
    Use `1` or higher; the system rejects values less than `1`.
  </Step>

  <Step title="Enable the configuration" icon="check-circle" title-type="p">
    Set **Enabled** to **Yes** so the rule is active once you save it.\
    You can toggle this later without deleting the configuration.
  </Step>

  <Step title="Add discount tiers" icon="plus" title-type="p">
    Add one or more tier rows. For each row:

    - Enter the **Session count** threshold.
    - Select the **Discount** from your existing discount codes.

    The configuration requires at least one complete tier row to save successfully.
  </Step>

  <Step title="Save the configuration" icon="check-circle" title-type="p">
    Review your tiers and settings, then click **Save**.\
    On success, the configuration appears in the multi-session list and will apply to new qualifying registrations.
  </Step>
</Steps>

### Edit or delete a multi-session configuration

<Steps>
  <Step title="Edit a configuration" icon="edit" title-type="p">
    In the multi-session list, click the pencil icon for the configuration you want to change.\
    Update the name, form, minimum sessions, enabled flag, or tier rows, then click **Save**.
  </Step>

  <Step title="Delete a configuration" icon="trash" title-type="p">
    Click the trash icon to remove a configuration entirely.\
    Confirm the deletion when prompted. After deletion, the rule no longer appears or applies at checkout.
  </Step>
</Steps>

You can disable a configuration temporarily by setting **Enabled** to **No**, instead of deleting it.

## Best practices

<Callout kind="tip" collapsed="false">
  Use these guidelines to keep discounts clear for both staff and families.
</Callout>

- Use clear, easy-to-type discount codes families can understand.
- Write descriptions that make sense on invoices and statements; avoid internal shorthand.
- Use date windows for time-limited promotions like early-bird or holiday specials.
- Prefer **Archive** over **Delete** when you want to preserve history for reporting and audits.
- Test discounts with a sample checkout, including multi-session rules, before announcing them.
- For multi-session tiers, keep thresholds simple and predictable so staff can explain them easily.

## Troubleshooting

Use this section when you see an error while saving a discount or multi-session configuration, or when a discount does not apply as expected.

<ExpandableGroup>
  <Expandable title="Error: You must enter a Discount Code" default-open="false">
    The system shows **You must enter a Discount Code** when you leave the **Discount Code** field blank while creating or editing a discount.

    Fix it by entering a code:

    - Use only letters and numbers.
    - Make the code short and easy to type.
    - Save again after adding the code.
  </Expandable>

  <Expandable title="Error: Discount Code can only be letters and numbers." default-open="false">
    The system shows **Discount Code can only be letters and numbers.** when the code includes any character that is not a letter or a number.

    Update the code to use only letters and numbers, then save the discount again.
  </Expandable>

  <Expandable title="Error: Discount code already exists" default-open="false">
    When you try to save a discount with a code that another discount already uses, you see **Discount code already exists**.

    To resolve this:

    - Choose a different, unique code.
    - Search the Discounts list to confirm how the existing code is used.
    - Save the new discount with a distinct code.
  </Expandable>

  <Expandable title="Error: You must enter a Discount Description" default-open="false">
    If you leave the **Discount Description** blank, the system returns **You must enter a Discount Description**.

    Enter a clear description that will appear on invoices, then save again.
  </Expandable>

  <Expandable title="Error: Only amount or percent can be greater than zero" default-open="false">
    The system enforces that only one of **Fixed Amount** or **Percent** is positive. When both fields are greater than zero, you see **Only amount or percent can be greater than zero**.

    Fix it by:

    - Keeping the field you want (amount or percent) as a positive number.
    - Setting the other field to `0` or leaving it empty.
    - Saving the discount again.
  </Expandable>

  <Expandable title="Discount is not showing for families at checkout" default-open="false">
    If families cannot see or use a discount code in the parent portal, check the following:

    - **Allow On Portal? = Yes** on the discount.
    - The current date is between the discount's **Start Date** and **End Date**, or both are blank.
    - The **Limit** has not been reached. If usage equals the limit, the discount no longer applies.
    - Product restrictions match the items in the cart; the discount applies only to qualifying products.
    - The discount is not archived and its status indicates it is in use.
    - For a pay in full discount, confirm the form's new pay in full setting is enabled or overridden correctly, and verify the discount is available for the full-balance checkout path.

    After adjusting settings, test again with a sample registration.
  </Expandable>

  <Expandable title="Multi-session discounts are not applying" default-open="false">
    If a multi-session discount does not apply when expected:

    - Confirm the configuration is **Enabled**.
    - Check that the **Minimum Sessions** is met by the registrant's qualifying sessions.
    - Make sure registrations are for products and forms that the configuration covers.
    - Verify each tier row has both a **Session count** and a valid **Discount** selected.
    - Confirm the discount codes used in tiers are active and not archived or expired.

    Save any fixes and test again with a multi-session registration.
  </Expandable>

  <Expandable title="Error: Name is required." default-open="false">
    When saving a multi-session configuration without a **Name**, the system returns **Name is required.**

    Enter a clear internal name for the configuration and save again.
  </Expandable>

  <Expandable title="Error: Minimum sessions must be at least 1." default-open="false">
    If you set **Minimum Sessions** to zero or a negative number, the system shows **Minimum sessions must be at least 1.**

    Update **Minimum Sessions** to `1` or higher, then save again.
  </Expandable>

  <Expandable title="Error: At least one discount tier is required." default-open="false">
    When you save a multi-session configuration without any valid tier rows, you see **At least one discount tier is required.**

    Add at least one tier row with both:

    - A **Session count**, and
    - A selected **Discount** from your existing codes.

    Then save the configuration.
  </Expandable>

  <Expandable title="Error: Access denied. when saving multi-session configuration" default-open="false">
    If your role does not have permission to manage multi-session configurations, the system can respond with **Access denied.** when you attempt to save.

    In this case:

    - Do not keep retrying the same action.
    - Contact your Campium admin or system owner to request the required access or to have them create the configuration for you.
  </Expandable>
</ExpandableGroup>

## Discount Checker

When a discount code does not work at checkout and the cause is not obvious, use the **Discount Checker** panel on the Discounts page to find the problem. The checker is a standalone panel on the page — not a per-row action. You pick a discount from a dropdown, pick the products involved, and optionally pick a user, then run it. It runs a series of checks against the discount and the products, then lists every issue it finds — sorted by severity so the most critical problems appear first.

### What the tool checks

The check runs three layers of checks:

<ExpandableGroup>
  <Expandable title="Discount-level checks" default-open="false">
    - Does the code exist with an exact case-sensitive match?
    - Is the discount public (visible to families in the portal)?
    - Is the discount archived?
    - Has the usage limit been reached?
    - Is the amount or percent set to zero?
    - Is the current date outside the discount's start or end date?
  </Expandable>

  <Expandable title="Product-level checks" default-open="false">
    - Is the product configured to allow discounts?
    - Is the product visible and active?
    - Has the product expired?
    - Is the product in the discount's restricted product list?
    - Do any registration forms that include this product have discounts disabled?
  </Expandable>

  <Expandable title="Cart simulation" default-open="false">
    - Builds a test cart with the selected products and runs the real checkout calculation engine.
    - Checks whether the discount would apply to that cart.
    - If you provide a specific user, checks for duplicate-discount status and capacity limits.
    - Predicts the exact error message a parent would see at checkout.
  </Expandable>
</ExpandableGroup>

### Run a check

<Steps>
  <Step title="Open the Discount Checker" icon="stethoscope" title-type="p">
    Go to **Admin** > **Discounts** and find the **Discount Checker** panel on the page.
  </Step>

  <Step title="Pick a discount" icon="tag" title-type="p">
    Choose the discount you want to investigate from the dropdown of your existing discounts.
  </Step>

  <Step title="Select products to test" icon="package" title-type="p">
    Choose one or more session products to test the discount against. The tool checks each product individually and as part of a simulated cart.
  </Step>

  <Step title="Optionally add a user" icon="users" title-type="p">
    Select a specific family to check for duplicate-discount status and enrollment capacity. Leave this blank to test without user-specific checks.
  </Step>

  <Step title="Run the check and review the results" icon="clipboard-list" title-type="p">
    Run the check. The tool returns a list of issues sorted by severity: **ERROR** items block the discount from working, **WARN** items may cause unexpected behavior, and **INFO** items are for awareness. Each issue includes a plain-language explanation and the predicted checkout message if applicable.
  </Step>

  <Step title="Fix and re-test" icon="refresh-cw" title-type="p">
    Address each error, then run the check again to confirm the discount works. The tool reflects your saved changes, so save any edits before re-running.
  </Step>
</Steps>

## Frequently asked questions

<ExpandableGroup>
  <Expandable title="How do I create a discount?" default-open="false">
    Go to **Admin** > **Discounts**, click **Add New Discount**, fill in the code, description, and amount or percent, then click **Save**. For the complete field-by-field walkthrough, see **Create a new discount** above.
  </Expandable>

  <Expandable title="How do I make a discount?" default-open="false">
    Creating a discount starts the same way: open **Admin** > **Discounts**, click **Add New Discount**, enter the discount details, and save. The full walkthrough is in **Create a new discount** above.
  </Expandable>

  <Expandable title="How do I edit a discount?" default-open="false">
    Find the discount in the list on the Discounts page, open its action menu, and choose **Edit Discount**. Update the fields you need, then click **Save**.
  </Expandable>

  <Expandable title="How do I delete a discount?" default-open="false">
    Open the action menu on the discount row and choose **Delete Discount**, then confirm the deletion. This is a hard delete and cannot be undone, so use **Archive Discount** instead if you want to keep the history.
  </Expandable>

  <Expandable title="How do I archive a discount?" default-open="false">
    Open the action menu on the discount row and choose **Archive Discount**. The discount stops applying to new checkouts, but its usage history stays available.
  </Expandable>

  <Expandable title="How do I make a discount available to parents in the portal?" default-open="false">
    Set **Allow On Portal?** to **Yes** when you create or edit the discount. Parents can then enter the code during checkout in the parent portal.
  </Expandable>

  <Expandable title="How do I make a discount staff-only?" default-open="false">
    Set **Allow On Portal?** to **No**. That keeps the discount in Admin only, so parents cannot see or use the code themselves.
  </Expandable>

  <Expandable title="How do I limit how many times a discount can be used?" default-open="false">
    Enter a number in the **Limit** field when you create or edit the discount. After the discount reaches that many uses, it stops working; leave the field blank or set it to `0` for no limit.
  </Expandable>

  <Expandable title="How do I set a discount to expire on a certain date?" default-open="false">
    Set the **End Date** when you create or edit the discount. The discount will not apply after that date, and you can also set a **Start Date** if you want to control when it becomes active.
  </Expandable>

  <Expandable title="How do I create a percentage discount?" default-open="false">
    Enter the percentage in the **Percent** field, such as `10` for ten percent off, and leave **Fixed Amount** at `0`. Only one of those fields can be greater than zero at a time.
  </Expandable>

  <Expandable title="How do I set up a pay in full discount?" default-open="false">
    Create the discount with the amount or percent you want, then turn on **Bypass payment at portal checkout?** if the discount should cover the full checkout amount. See the **Configure a pay in full discount** step in **Create a new discount** for the related settings.
  </Expandable>

  <Expandable title="How do I apply a discount to only certain products?" default-open="false">
    Use **Apply Only To These Products** to pick the products that should qualify. If you leave the product list blank, the discount can apply across all eligible products. This control is independent of **Apply To All Sessions**, which only affects how a percent discount spreads across a child's sessions.
  </Expandable>

  <Expandable title="How do I set up a multi-session discount?" default-open="false">
    Scroll to **Multi-Session Discount Configurations** on the Discounts page, click **Add Multi-Session Discount**, name the rule, set the minimum session count, and add tier rows that link session counts to existing discount codes. For the full process, see **Create a multi-session configuration** above.
  </Expandable>

  <Expandable title="How do I stop a discount from being used?" default-open="false">
    Archive the discount, set an **End Date** in the past, or set the **Limit** to a number that has already been reached. Archiving is usually the best option because it stops new use while preserving history.
  </Expandable>

  <Expandable title="Can the same family use a discount more than once?" default-open="false">
    Yes, if **Allow Duplicate?** is set to **Yes** when you create or edit the discount. Set it to **No** if you want to limit the discount to one use per user.
  </Expandable>

  <Expandable title="How do I preview a discount before saving?" default-open="false">
    Open the discount editor (Add New Discount or Edit Discount), fill in your settings, then use the **Discount Calculator** panel to pick real families and sessions. Click **Preview** to see exactly how the discount will apply at checkout. See **Discount Calculator** above for full steps.
  </Expandable>

  <Expandable title="How do I test a discount before saving?" default-open="false">
    Use the Discount Calculator built into the discount editor. It runs the real checkout pricing engine against the families and sessions you pick, so you see the actual amounts without creating any records. See **Discount Calculator** above.
  </Expandable>

  <Expandable title="Why is my discount code not working?" default-open="false">
    Use the **Discount Checker** panel on the Discounts page. Pick the discount from the dropdown, select the products involved, and optionally pick a user, then run the check. The tool runs a full set of checks and lists every issue sorted by severity. See **Discount Checker** above.
  </Expandable>

  <Expandable title="How do I check a discount code problem?" default-open="false">
    Go to **Admin** > **Discounts** and use the **Discount Checker** panel. Pick the discount from the dropdown, select the session products to test against, optionally add a user, then run the check and review the results. Errors are listed first so you can fix the blocking issues. See **Discount Checker** above.
  </Expandable>

  <Expandable title="How do I skip a deposit with a discount?" default-open="false">
    Turn on **Bypass payment at portal checkout?** when you create or edit the discount. Parents can then submit their registration without entering a card or ACH payment, so they proceed without paying the upfront amount. You can also add a dollar or percent credit alongside it. See **Bypass payment at portal checkout** above.
  </Expandable>

  <Expandable title="How do I make a discount waive the deposit?" default-open="false">
    Same setting: turn on **Bypass payment at portal checkout?** on the discount. There is no separate "Skip Deposit?" toggle — this one field lets the family submit at checkout without paying. See **Bypass payment at portal checkout** above.
  </Expandable>
</ExpandableGroup>
