## What you can do with Discounts

On the Discounts page you manage discount codes, the sibling discount, and multi-session discount rules. Discounts control how much families save, when they qualify, and whether staff or families can apply them at checkout.

Use this page when you want to:

- Create new discount codes for promotions or financial aid
- Create a **Sibling discount** that applies automatically when a family has two or more children in the same season (in one checkout or across separate registrations)
- Edit, archive, or delete existing discounts
- Control when and where a discount can be used
- Set up multi-session discounts that reward additional registrations
- Let a discount cover the full checkout amount so families do not need to pay anything at checkout

<Callout kind="info" collapsed="false">
  Discounts change how much families pay at checkout. Check how a change affects your pricing and invoices before you save it.
</Callout>

## Open the Discounts page

<Steps>
  <Step title="Open the Admin menu" icon="settings" title-type="p">
    From the left sidebar, click **Admin**.
  </Step>

  <Step title="Go to Discounts" icon="settings" title-type="p">
    In the Admin menu, click **Discounts**.
  </Step>
</Steps>

The page lists your active discounts. Use **Show Me** to switch between **Active** and **Archived** discounts. The **Code Checker**, **Multi-Session**, and **Pay In Full Default** buttons above the list each open a panel for that tool.

## Family-level discounts on a profile

You can also post a discount from a person's profile instead of using a checkout code.

1. Open the profile and go to the **Sales** tab.
2. Click **Add Payment**.
3. Set **Payment Type** to a discount option (the form shows a **Discount** field once that type is selected).
4. In **For User**, leave **Entire family** selected when the discount is not for one camper.
5. Choose a specific family member only when the discount should sit on that person alone.
6. When you save, Campium rebuilds the payment plan from the new balance when a plan is on the sale. If there is no plan, it trims upcoming scheduled payments from the latest installment first so the remaining schedule still matches what is owed.

On family invoices, a camper-specific discount appears in that camper's section. A family-level discount appears in its own block for the family. The invoice **Payments** section uses a **Payment** column header and matches the styling of the **Discounts** section.

## Discount list: columns and status

Each row in the discount list is one discount.

<ParamField body="code" param-type="string" required="false" deprecated="false" show-location="false">
  **Code** - The code families or staff enter at checkout. Sibling discounts show a **Sibling** badge next to the code.
</ParamField>

<ParamField body="description" param-type="string" required="false" deprecated="false" show-location="false">
  **Description** - The text that appears on invoices and receipts. Use wording families recognize.
</ParamField>

<ParamField body="status" param-type="string" required="false" deprecated="false" show-location="false">
  **Status** - Whether the discount can be used now:

  - **In Use**: The discount is active and applies when its other conditions are met.
  - **Not in use**: You set **Status** to **No Longer In Use** on the discount.
  - **Expired**: The discount is past its end date.
</ParamField>

<ParamField body="amount" param-type="number" required="false" deprecated="false" show-location="false">
  **Amount** - The fixed dollar amount or the percent.
</ParamField>

<ParamField body="public" param-type="boolean" required="false" deprecated="false" show-location="false">
  **Public?** - Whether families can use the code in the parent portal:

  - **Yes**: Parents can enter this code at checkout.
  - **No**: Only staff can apply it from Admin.
</ParamField>

<ParamField body="bypassPay" param-type="boolean" required="false" deprecated="false" show-location="false">
  **Bypass pay?** - Whether the code lets parents submit portal checkout without a card or ACH payment. This is the **Bypass payment at portal checkout?** setting.
</ParamField>

<ParamField body="allowDuplicates" param-type="boolean" required="false" deprecated="false" show-location="false">
  **Allow Duplicates?** - Whether the same user can receive the discount more than once:

  - **Yes**: The same user can use this discount multiple times.
  - **No**: The user can only receive this discount once.
</ParamField>

<ParamField body="usage" param-type="integer" required="false" deprecated="false" show-location="false">
  **Usage** - How many times the discount has been used. Click the number to see who used it.
</ParamField>

<ParamField body="limit" param-type="integer" required="false" deprecated="false" show-location="false">
  **Limit** - The maximum number of uses, if you set one. Blank or zero means no limit.
</ParamField>

<ParamField body="maxTotal" param-type="string" required="false" deprecated="false" show-location="false">
  **Max Total** - How much of the code's dollar budget has been given away, when you set a **Maximum Total**. Shows as used-of-cap (for example `250.00 of 500.00`). Shows **None set** when there is no dollar cap.
</ParamField>

<ParamField body="startEndDate" param-type="string" required="false" deprecated="false" show-location="false">
  **Start Date / End Date** - The date range when the discount is valid. Outside this window, the discount does not apply.
</ParamField>

### Edit fields on the Discounts list

You can change several columns on the list without opening the full discount editor. Click the blue value in the cell, edit it, then leave the field (or press Enter) to save. Empty optional values show **None set**.

Columns you can edit inline:

- **Description** (title: **Edit description**)
- **Status** (**In Use** / **Not in use**; title: **Edit status**)
- **Amount** (title: **Edit amount**)
- **Public?** (**Yes** / **No**; title: **Edit public**)
- **Bypass pay?** (**Yes** / **No**; title: **Edit bypass pay**)
- **Allow Duplicates?** (**Yes** / **No**; title: **Edit allow duplicates**)
- **Limit** (title: **Edit limit**)
- **Max Total** (title: **Edit maximum total**; sibling-discount rows keep limit and max total read-only)
- **Start Date** / **End Date** (empty cells show **None set**; **Save** or **Cancel**)

On **Seasons** → a season's **Guided setup** → **Discounts**, the **Dates** column uses the same date editor, with lines labeled **Starts** and **Ends** (empty state **None set**).

Use the action menu on each row when you need the full editor, or to archive or delete a discount.

## Create a new discount

Create a discount to run a promotion, offer financial aid, make a staff-only adjustment, reward paying in full, let a family check out without paying, or set up the automatic sibling discount.

<Steps>
  <Step title="Start a new discount" icon="plus" title-type="p">
    Click **Add New Discount** on the Discounts page.
  </Step>

  <Step title="Choose the discount type" icon="settings" title-type="p">
    Under **Discount Type**, choose:

    - **Code discount**: families type a code at checkout (or staff apply it in Admin).
    - **Sibling discount**: applied automatically when a family has two or more children enrolled or registering in the same season. The highest-priced child pays full price; the second child gets the rate you set, and you can add different rates under **Third Child And Beyond**.

    You can have only one sibling discount. If one already exists, **Sibling discount** is disabled and a link to **Edit it** appears.
  </Step>

  <Step title="Enter code and description" icon="edit" title-type="p">
    For a **Code discount**:

    - Fill in **Discount Code**. This is what families or staff enter at checkout.
    - Fill in **Discount Description**. This appears on invoices and receipts.

    When you choose **Sibling discount**, the code field is hidden, and an empty **Discount Description** fills in with **Sibling Discount**.
  </Step>

  <Step title="Set the discount value" icon="edit" title-type="p">
    Enter either:

    - **Fixed Amount** (for example, `25.00` for a twenty-five dollar discount), or
    - **Percent** (for example, `10` for ten percent off)

    Leave the other field blank or at zero. Only one of the two can be greater than zero.

    <Image src="https://raw.githubusercontent.com/cary42/documentationai-Docs/main/images/walkthroughs/new-discount-code-amount.png" width="1140" height="844" alt="New Discount with a code, a description and a 10 percent amount filled in" />
  </Step>

  <Step title="Optionally limit total uses" icon="settings" title-type="p">
    For a **Code discount**, enter the maximum number of uses in **Limit**.\
    Leave blank or enter `0` for no limit. Sibling discounts do not use Limit.
  </Step>

  <Step title="Optionally cap the total dollars given away" icon="settings" title-type="p">
    For a **Code discount**, in **Maximum Total**, enter the maximum dollar amount this code can give away across all redemptions (for example `500` or `1,500.00`). Leave blank for no dollar limit.

    **Limit** caps how many times the code can be used. **Maximum Total** caps how many dollars it can give away. A 10% code with a `$500` maximum stops once `$500` has been discounted. Sibling discounts hide this field.

    <Image src="https://raw.githubusercontent.com/cary42/documentationai-Docs/main/images/walkthroughs/new-discount-limits.png" width="1140" height="664" alt="The lower half of New Discount: Allow On Portal, Limit, Maximum Total and the date range" />
  </Step>

  <Step title="Choose how a percent discount applies across sessions" icon="settings" title-type="p">
    Set **Apply To All Sessions** (default **Yes**):

    - **Yes**: A percent discount applies to every eligible session for that child.
    - **No**: A percent discount applies only to the child's lowest-priced session.
  </Step>

  <Step title="Choose how sessions are counted across children" icon="settings" title-type="p">
    For a **Code discount**, set **Combine All Children's Sessions** (default **No**) to control how a percent discount is calculated when a family has more than one child:

    - **Yes**: The discount is computed across all children's sessions combined.
    - **No**: The discount is computed separately for each child.

    Sibling discounts hide this setting and always calculate per child (not combined across the cart).
  </Step>

  <Step title="Configure a pay in full discount" icon="check-circle" title-type="p">
    The automatic discount for families who choose pay in full is not a code. Set it with the **Pay In Full Default** button on the Discounts page: pick **Discount Type** (**Fixed Amount** or **Percent**), enter **Default Value**, and click **Save Pay In Full Default**. Then turn it on for a form with **Enable Pay In Full Discount** on that form's **Settings** tab, where you can also override the type and value.

    To reward paying in full with a code instead, create a code discount with a **Fixed Amount** or **Percent**.

    To let a family check out without paying, set **Bypass payment at portal checkout?** to **Yes** (default **No**). Parents can then submit their registration without entering a card or ACH payment.

    For a code discount used this way:

    - Set **Allow On Portal?** to **Yes** if families should apply it in the parent portal.
    - Set **Start Date** and **End Date** if the discount should only apply during a specific registration window.
    - Set **Limit** if you want to cap how many pay in full discounts can be used.
    - Set **Maximum Total** if you want to cap the total dollars the code can give away.
    - Use **Apply Only To These Products** to control which registrations qualify.
  </Step>

  <Step title="Control who can use the discount" icon="users" title-type="p">
    For a **Code discount**, set **Allow On Portal?** (default **Yes**):

    - **Yes**: Families can enter the code during checkout in the parent portal.
    - **No**: Only staff can apply the discount in Admin.

    Sibling discounts always apply on the portal automatically, so this setting is hidden.
  </Step>

  <Step title="Control repeat usage" icon="settings" title-type="p">
    For a **Code discount**, set **Allow Duplicate?** (default **No**):

    - **Yes**: The same user can receive the discount multiple times.
    - **No**: The discount applies at most once per user.

    Sibling discounts hide this setting.
  </Step>

  <Step title="Choose calculation order" icon="settings" title-type="p">
    Set **Apply After Other Discounts?** (default **No**):

    - **Yes**: Calculate this discount after other discounts.
    - **No**: Use standard calculation order with other discounts.
  </Step>

  <Step title="Add optional date window" icon="calendar" title-type="p">
    Set **Start Date** and **End Date** to control when the discount is active. **End Date** is the last day the discount works.\
    Leave both blank to allow use at any time, subject to the other settings.
  </Step>

  <Step title="Target specific products (optional)" icon="package" title-type="p">
    In **Apply Only To These Products**, select the products the discount applies to. The last word of this label is your camp's term for products, such as **Sessions**.\
    Leave it blank to apply the discount to all eligible products.
  </Step>

  <Step title="Save the discount" icon="check-circle" title-type="p">
    Click **Save**.\
    The page reloads and the discount appears in the list.
  </Step>
</Steps>

<Callout kind="tip" collapsed="false">
  Test a new discount with a sample registration before you announce it. Confirm the amount, visibility, and invoice description. For sibling discounts, try both paths: register two or more children in one checkout, and register a second child after the first is already enrolled. Confirm the highest-priced child pays full price, the second child gets the base sibling rate, and any **Third Child And Beyond** rows apply when you set them.
</Callout>

## Create a sibling discount

A **Sibling discount** applies automatically at checkout when a family has two or more children in the same season. That includes registering them together, or registering another child after a sibling is already enrolled. Campium ranks those children by the price of the sessions this discount applies to, so transportation or other add-ons outside that scope do not change who pays full price. The highest-priced child in that ranking pays full price. The second child gets the rate you set on the discount. Families do not type a code.

Waitlisted and cancelled enrollments do not count toward the sibling ranking.

<Steps>
  <Step title="Open Add New Discount" icon="plus" title-type="p">
    Go to **Admin → Discounts** and click **Add New Discount**.
  </Step>

  <Step title="Select Sibling discount" icon="users" title-type="p">
    Under **Discount Type**, choose **Sibling discount**. A note on the form explains that the highest-priced child pays full price and the second child gets the rate you set here. Checkout also counts siblings who are already enrolled in the same season, so a second registration alone still qualifies.
  </Step>

  <Step title="Set the second-child rate and description" icon="edit" title-type="p">
    Enter a **Fixed Amount** or **Percent** for the second child, and confirm **Discount Description** (filled in as **Sibling Discount** if it was blank).

    For a percent, enter `5` for 5%, not `.05`.
  </Step>

  <Step title="Set remaining rules and save" icon="check-circle" title-type="p">
    Set **Apply To All Sessions**, **Apply After Other Discounts?**, dates, and product restrictions as needed, then click **Save**.

    The code-only fields (**Discount Code**, **Combine All Children's Sessions**, **Allow On Portal?**, **Bypass payment at portal checkout?**, **Allow Duplicate?**, **Limit**, and **Maximum Total**) are hidden for a sibling discount.
  </Step>

  <Step title="Optional: add rates for the third child and beyond" icon="users" title-type="p">
    After you save, open the sibling discount again. Use **Third Child And Beyond** to give later children different rates.

    1. Click **Add another child** to add a row.
    2. Each row shows a label such as **3rd Child**, with **Amount** and **Percent** fields.
    3. Click **Remove** on a row you do not need.
    4. Leave **Third Child And Beyond** empty if every child after the highest-priced one gets the second-child rate.

    A child only receives a discount at a level you have set up, so add a row for each deeper child you want to cover. The discount list can show more than one rate (for example `5 / 8%`) when tiers exist.
  </Step>

  <Step title="Optional: set amount by weeks enrolled" icon="calendar" title-type="p">
    In the same editor, use **Amount By Weeks Enrolled** to give a child a set dollar amount based on how many weeks they attend, instead of the fixed or percent rate above.

    1. Click **Add a weeks range**.
    2. Each row has **Child** (which sibling tier), **From** and **To** (week counts), and **Amount**.
    3. Click **Remove** on a row you do not need.
    4. Weeks are counted from the sessions this discount applies to. A child whose weeks fall outside every range gets no sibling discount.

    On the discount list, the Amount cell can show **By weeks enrolled** when bands are set.
  </Step>
</Steps>

If you already have a sibling discount, **Add New Discount** disables **Sibling discount** and links to the existing one. On the discount list, sibling rows show a **Sibling** badge. When you edit a sibling discount, **Discount Type** shows **Sibling Discount** instead of a code field.

### After you remove or switch a session

When a sibling discount on file no longer matches after you remove or switch a session on a profile, Campium can ask **Update the sibling discount?** with **Camper**, **On file**, and **Calculated**. Choose **Update it** or **Not now**. See [Withdraw a camper](/withdraw-a-camper).

## Edit, archive, or delete a discount

Use the action menu on each discount row to update or remove a discount.

<Steps>
  <Step title="Open the action menu" icon="settings" title-type="p">
    In the discount list, click the action menu for the discount you want to change.
  </Step>

  <Step title="Edit a discount" icon="edit" title-type="p">
    Choose **Edit Discount** to change fields such as amount, dates, or description, then click **Save**. **Edit Discount** also has a **Status** field (**In Use** or **No Longer In Use**). Changes affect new uses of the discount.
  </Step>

  <Step title="Archive a discount" icon="archive" title-type="p">
    Choose **Archive Discount** to stop using a discount but keep its history.\
    Archived discounts leave the active list and no longer apply to new checkouts. To see them, set **Show Me** to **Archived**.
  </Step>

  <Step title="Delete a discount" icon="trash" title-type="p">
    Choose **Delete Discount** to permanently remove the discount from your account.\
    Confirm the deletion when prompted. **Delete Discount** appears only for a discount that has never been used. For a discount that has been applied, archive it instead.
  </Step>
</Steps>

<Callout kind="alert" collapsed="false">
  Deleting a discount removes it permanently and cannot be undone. Use **Archive Discount** to stop a discount that already has usage history.
</Callout>

## Key settings explained

### Public vs non-public discounts

**Allow On Portal?** (the **Public?** column on the list) controls who can apply a discount.

- **Yes**: Parents can enter the code themselves in the parent portal during checkout.
- **No**: Staff apply the discount manually from a profile; parents cannot use the code.

Public discounts suit general promotions. Non-public discounts suit case-by-case adjustments and internal programs.

### Limit (capacity)

Limit controls how many times a discount can be used across all families.

- **Blank or 0**: No usage cap. Date range and other rules still apply.
- **Any positive number**: The discount stops working after it reaches that many successful uses.

Use limits for early-bird specials, limited-seat promotions, or grants with fixed budgets.

**Limit** does not block staff from applying the code by hand in Admin once the use count is reached. **Maximum Total** does block staff when the dollar budget is gone or the next redemption would overshoot it.

### Maximum Total

**Maximum Total** caps how many dollars a code discount can give away in total. It sits below **Limit** on **Add New Discount** and **Edit Discount**.

- **Blank or 0**: No dollar cap.
- **A dollar amount** (for example `500` or `1,500.00`): the code stops once that much has been discounted. `$` signs and commas are accepted when you save.

How it behaves:

- Redeemed dollars are the net amount already credited for that code. Refunding a discount restores budget.
- A redemption that would go over the remaining budget is refused whole. It is never trimmed to what is left, so no family gets less than the code advertises.
- On edit, helper text shows how much has been used and how much is left (or that the code is spent out). The discount list **Max Total** column shows used-of-cap when a cap is set.
- Families who try a spent-out or overshooting code see **Sorry. This discount is no longer valid.** (Usage-limit refusals still say **Sorry. This discount is no longer available.**) Staff who apply or raise a discount past the cap see a message that names the code, the maximum total, how much has been used, and what is left.

Sibling discounts do not use **Maximum Total**.

### Date range

Start and end dates control when a discount is active.

- If you set a **Start Date**, the code cannot be used before that date.
- If you set an **End Date**, the code stops working after that date.
- If you leave both blank, the discount stays active until you archive or delete it, or it hits a limit.

Outside its date range, the discount does not apply and families and staff see an error.

### Product restriction

Product restrictions control where a discount applies.

- If you select one or more products in **Apply Only To These Products**, the discount applies only to those products.
- If you leave it blank, the discount can apply to all eligible products.

Use product restrictions to limit discounts to certain camps, add-ons, or seasons.

### Bypass payment at portal checkout

A discount can skip payment at checkout instead of only reducing the price. When **Bypass payment at portal checkout?** is **Yes**, parents can submit their registration in the parent portal without entering a card or ACH payment. The setting still respects **Allow On Portal?**, dates, **Limit**, and duplicate rules.

You can combine this setting with a dollar or percent credit: payment is bypassed at checkout and the credit is applied to the balance. Use it for scholarships, financial aid agreements, or promotions where you want to remove the upfront payment without changing tuition. With bypass on, you can leave both **Fixed Amount** and **Percent** blank.

This is the setting people call skipping the deposit. There is no separate toggle.

After a family enters a bypass code, they can still pick a payment plan or switch between card and bank. The bypass stays applied through those recalculations. For a code with no amount or percent, the cart shows a line ending in **payment deferred**. Removing that discount from the cart ends the bypass, and checkout asks for payment again.

## Discount Calculator

The **Preview** panel on the right side of **Add New Discount** and **Edit Discount** shows how a discount will apply at checkout before you save it. Pick real people and sessions, and the preview runs the same pricing engine checkout uses, including tiered pricing, sibling discounts, and multi-session tiers, to show an itemized breakdown. Nothing is saved.

<Callout kind="info" collapsed="false">
  The preview uses the checkout calculation engine, so the amounts match what families are charged. It creates no sales, carts, or payment records.
</Callout>

<Steps>
  <Step title="Open the discount editor" icon="edit" title-type="p">
    Go to **Admin → Discounts** and click **Add New Discount**, or edit an existing discount. The **Preview** panel is on the right of the form.
  </Step>

  <Step title="Enter your discount settings" icon="settings" title-type="p">
    Fill in the code, amount or percent, date range, product restrictions, and other settings. The preview uses what is in the form now, including unsaved changes.
  </Step>

  <Step title="Add people to the preview" icon="users" title-type="p">
    For each user block, type a name to pick a person, then choose their sessions. Click **Add another user** to add more, up to 6 people with up to 40 sessions each. The preview uses each person's real tiered pricing.
  </Step>

  <Step title="Review the preview" icon="calculator" title-type="p">
    Click **Calculate**. For each person you see their sessions total, each discount line applied (the discount you are editing, sibling discounts, and multi-session tier discounts), and the **Net** amount after discounts. An **Order total** line shows the combined totals.
  </Step>

  <Step title="Check for warnings" icon="alert-triangle" title-type="p">

  <Step title="Adjust and re-preview" icon="refresh-cw" title-type="p">
    Change any setting in the form. The preview recalculates on its own after each change.

  <Step title="Save when satisfied" icon="check-circle" title-type="p">
    When the preview looks right, click **Save**.
  </Step>
</Steps>

You can pick several sessions per person, so you can preview discounts that target specific products or apply to all eligible sessions. The sibling discount is included when you add more than one child.

## Multi-session discounts

Multi-session discounts reward a registrant who enrolls in several qualifying sessions. These rules work on top of your regular discounts and use existing discount codes as tiers.

### Access and permissions

Anyone who can open the Discounts page can manage multi-session configurations. The **Multi-Session** button uses the same permission as the Discounts page itself.

<Callout kind="info" collapsed="false">
  Multi-session configurations are global pricing rules. Limit access to staff who manage tuition policies and discounts across your organization.
</Callout>

### What a multi-session configuration includes

Each multi-session configuration defines a volume-based discount rule.

<ParamField body="name" param-type="string" required="false" deprecated="false" show-location="false">
  **Name** - Internal label for the rule, such as `Summer Session Volume Discount`.
</ParamField>

<ParamField body="form" param-type="string" required="false" deprecated="false" show-location="false">
  **Form (optional)** - Limits the rule to one registration form. The default, **All forms**, applies it everywhere.
</ParamField>

<ParamField body="minimumSessions" param-type="integer" required="false" deprecated="false" show-location="false">
  **Minimum Sessions** - The number of qualifying sessions required before the rule applies a discount. Defaults to `2`.
</ParamField>

<ParamField body="enabled" param-type="boolean" required="false" deprecated="false" show-location="false">
  **Enabled** - Turns the rule on or off without deleting it. Disabled rules do not apply at checkout.
</ParamField>

<ParamField body="discountTiers" param-type="array" required="false" deprecated="false" show-location="false">
  **Discount Tiers** - One or more tier rows. Each tier sets:

  - A **Session Count** threshold.
  - A **Discount** chosen from your existing discount codes that applies when the threshold is met.
</ParamField>

### Before you build multi-session rules

Multi-session tiers use discount codes you have already created. Create the codes on the Discounts list first, then choose them in your tiers.

This keeps invoice descriptions consistent and lets you reuse a discount in more than one place.

### How tiers work

Tiers are based on session counts. Campium counts a registrant's qualifying sessions and picks the matching tier.

- When a registrant reaches a tier's **Session Count**, they qualify for that tier's discount.
- If several tiers qualify, the highest threshold they meet applies.

**Example**

- Tier for **2 sessions** → uses discount code `MULTI2`.
- Tier for **4 sessions** → uses discount code `MULTI4`.

If a registrant has 5 qualifying sessions, the 4-session tier applies.

### Create a multi-session configuration

Use these steps from the **Multi-Session** panel on the Discounts page.

<Steps>
  <Step title="Open multi-session configurations" icon="settings" title-type="p">
    On the Discounts page, click **Multi-Session** to open the **Multi-Session Discount Configurations** panel.
  </Step>

  <Step title="Start a new configuration" icon="plus" title-type="p">
    Click **Add Multi-Session Discount** to open the configuration form.
  </Step>

  <Step title="Name and scope the rule" icon="edit" title-type="p">
    - Enter a **Name** to identify the rule internally.
    - Optionally choose a form in **Form (optional)** to limit where the rule applies, or leave **All forms** selected.
  </Step>

  <Step title="Set minimum sessions" icon="settings" title-type="p">
    In **Minimum Sessions**, enter the number of qualifying sessions required before any tier applies.\
    Use `1` or higher. Values below `1` are refused.
  </Step>

  <Step title="Enable the configuration" icon="check-circle" title-type="p">
    Leave **Enabled** at **Yes** so the rule is active once you save it.\
    You can change this later without deleting the configuration.
  </Step>

  <Step title="Add discount tiers" icon="plus" title-type="p">
    Click **+ Add Tier** for each extra row you need. For each row:

    - Enter the **Session count** threshold.
    - Select the **Discount** from your existing discount codes.

    You need at least one complete tier row to save.
  </Step>

  <Step title="Save the configuration" icon="check-circle" title-type="p">
    Click **Save**.\
    The configuration appears in the multi-session list and applies to new qualifying registrations.
  </Step>
</Steps>

### Edit or delete a multi-session configuration

<Steps>
  <Step title="Edit a configuration" icon="edit" title-type="p">
    In the multi-session list, click the pencil icon for the configuration you want to change.\
    Update the name, form, minimum sessions, enabled flag, or tier rows, then click **Save**.
  </Step>

  <Step title="Delete a configuration" icon="trash" title-type="p">
    Click the trash icon to remove a configuration entirely.\
    Confirm the deletion when prompted. The rule no longer appears or applies at checkout.
  </Step>
</Steps>

To pause a configuration without deleting it, set **Enabled** to **No**.

## Best practices

<Callout kind="tip" collapsed="false">
  These guidelines keep discounts clear for staff and families.
</Callout>

- Use short, easy-to-type codes.
- Write descriptions that make sense on invoices and statements; avoid internal shorthand.
- Use date windows for time-limited promotions like early-bird or holiday specials.
- Prefer **Archive** over **Delete** when you want to preserve history for reporting and audits.
- Test discounts with a sample checkout, including multi-session rules, before announcing them.
- Keep multi-session thresholds simple so staff can explain them.

## Troubleshooting

Use this section when you see an error saving a discount or multi-session configuration, or when a discount does not apply as expected.

<ExpandableGroup>
  <Expandable title="Error: You must enter a Discount Code" default-open="false">
    You see **You must enter a Discount Code** when you save a discount with **Discount Code** blank.

    Enter a code, keep it short and easy to type, and save again.
  </Expandable>

  <Expandable title="Error: Discount Code can only be letters and numbers." default-open="false">
    You see **Discount Code can only be letters and numbers.** when the code contains an ampersand (`&`).

    Remove the `&` and save the discount again.
  </Expandable>

  <Expandable title="Error: Discount code already in use." default-open="false">
    When you save a discount with a code another discount already uses, you see **Discount code already in use.** on **Add New Discount**, or **Code already exists. Try again.** on **Edit Discount**.

    To resolve this:

    - Choose a different, unique code.
    - Search the Discounts list to confirm how the existing code is used.
    - Save the new discount with a distinct code.
  </Expandable>

  <Expandable title="Error: You must enter a Discount Description" default-open="false">
    If you leave **Discount Description** blank, you see **You must enter a Discount Description**.

    Enter a description for invoices, then save again.
  </Expandable>

  <Expandable title="Error: Only amount or percent can be greater than zero" default-open="false">
    Only one of **Fixed Amount** or **Percent** can be greater than zero. When both are, **Add New Discount** and **Edit Discount** show **Only amount or percent can be greater than zero.** and the discount is not saved.

    Fix it by:

    - Keeping the field you want (amount or percent) as a positive number.
    - Setting the other field to `0` or leaving it empty.
    - Saving the discount again.
  </Expandable>

  <Expandable title="Error: Maximum Total must be a dollar amount like 500 or 1,500.00, or left blank for no limit." default-open="false">
    You see this when **Maximum Total** is not blank and is not a valid dollar amount. Letters, a bare decimal point, three decimal places, and negative numbers are refused.

    Enter a dollar amount such as `500` or `1,500.00`, or clear the field for no limit, then save again. Campium refuses the save rather than treat an invalid value as no cap.
  </Expandable>

  <Expandable title="Discount is not showing for families at checkout" default-open="false">
    If families cannot see or use a discount code in the parent portal, check the following:

    - **Allow On Portal? = Yes** on the discount.
    - The current date is between the discount's **Start Date** and **End Date**, or both are blank.
    - The **Limit** has not been reached. If usage equals the limit, the discount no longer applies.
    - **Maximum Total** has budget left. If the dollar cap is spent out, or the next redemption would overshoot what is left, families see **Sorry. This discount is no longer valid.**
    - Product restrictions match the items in the cart; the discount applies only to qualifying products.
    - The discount is not archived and its **Status** is **In Use**.
    - For the pay in full discount, **Enable Pay In Full Discount** is **Yes** on the form's **Settings** tab.

    After adjusting settings, test again with a sample registration.
  </Expandable>

  <Expandable title="Multi-session discounts are not applying" default-open="false">
    If a multi-session discount does not apply when expected:

    - Confirm the configuration is **Enabled**.
    - Confirm the registrant has at least **Minimum Sessions** qualifying sessions.
    - Make sure registrations are for products and forms that the configuration covers.
    - Verify each tier row has both a **Session count** and a valid **Discount** selected.
    - Confirm the discount codes used in tiers are active and not archived or expired.

    Save any fixes and test again with a multi-session registration.
  </Expandable>

  <Expandable title="Error: Name is required." default-open="false">
    You see **Name is required.** when you save a multi-session configuration without a **Name**.

    Enter a name and save again.
  </Expandable>

  <Expandable title="Error: Minimum sessions must be at least 1." default-open="false">
    If you set **Minimum Sessions** to zero or a negative number, you see **Minimum sessions must be at least 1.**

    Update **Minimum Sessions** to `1` or higher, then save again.
  </Expandable>

  <Expandable title="Error: At least one discount tier is required." default-open="false">
    When you save a multi-session configuration without any valid tier rows, you see **At least one discount tier is required.**

    Add at least one tier row with both:

    - A **Session count**, and
    - A selected **Discount** from your existing codes.

    Then save the configuration.
  </Expandable>

  <Expandable title="Error: Access denied. when saving multi-session configuration" default-open="false">
    You see **Access denied.** when your role does not have the permission that opens the Discounts page.

    Ask an administrator at your camp to give your role that access, or to create the configuration for you.
  </Expandable>
</ExpandableGroup>

## Discount Checker

When a discount code does not work at checkout and the cause is not obvious, click **Code Checker** on the Discounts page to open the **Discount Code Checker** panel. It is a panel on the page, not a row action. You pick a discount, the products in the cart, and optionally a checkout form and a camper, then run it. It checks the discount and the products and lists every issue it finds, most severe first.

### What the tool checks

The checker runs three layers of checks:

<ExpandableGroup>
  <Expandable title="Discount-level checks" default-open="false">
    - Does the code exist with an exact case-sensitive match?
    - Is the discount public (visible to families in the portal)?
    - Is the discount archived?
    - Has the usage limit been reached?
    - Has the **Maximum Total** dollar budget been spent, or would this redemption overshoot what is left?
    - Does the discount have no amount, no percent, and no payment bypass?
    - Is the current date outside the discount's start or end date?
  </Expandable>

  <Expandable title="Product-level checks" default-open="false">
    - Is the product configured to allow discounts?
    - Is the product visible and active?
    - Has the product expired?
    - Is the product in the discount's restricted product list?
    - Is the discount code field hidden on a form that includes this product?
  </Expandable>

  <Expandable title="Cart simulation" default-open="false">
    - Builds a test cart with the selected products and runs the checkout calculation engine.
    - Checks whether the discount would apply to that cart.
    - If you pick a camper, checks whether that camper already used the discount and whether the session is full.
    - Predicts the exact error message a parent would see at checkout.
  </Expandable>
</ExpandableGroup>

### Run a check

<Steps>
  <Step title="Open the Discount Checker" icon="stethoscope" title-type="p">
    Go to **Admin → Discounts** and click **Code Checker**.
  </Step>

  <Step title="Pick a discount" icon="tag" title-type="p">
    In **Discount code**, choose the discount to investigate.
  </Step>

  <Step title="Select products to test" icon="package" title-type="p">
    In the products-in-cart field, choose one or more products to test against. The label uses your camp's term, such as **Sessions in cart**. The checker tests each product on its own and as part of a simulated cart. Optionally pick a **Checkout form**.
  </Step>

  <Step title="Optionally add a user" icon="users" title-type="p">
    In **Camper**, search for a camper by name to check whether they already used the discount and whether the session is full. Leave it blank to skip those checks.
  </Step>

  <Step title="Run the check and review the results" icon="clipboard-list" title-type="p">
    Click **Run check**. The checker lists issues by severity: **ERROR** items stop the discount from working, **WARN** items may cause unexpected behavior, and **INFO** items are for your information. When the discount would fail, the list includes the message a parent would see at checkout.
  </Step>

  <Step title="Fix and re-test" icon="refresh-cw" title-type="p">
    Fix each error, then run the check again. The checker reads saved settings, so save your edits first.
  </Step>
</Steps>

## Frequently asked questions

<ExpandableGroup>
  <Expandable title="How do I create a discount?" default-open="false">
    Go to **Admin → Discounts**, click **Add New Discount**, fill in the code, description, and amount or percent, then click **Save**. For every field, see **Create a new discount** above.
  </Expandable>

  <Expandable title="How do I make a discount?" default-open="false">
    Open **Admin → Discounts**, click **Add New Discount**, enter the discount details, and click **Save**. See **Create a new discount** above.
  </Expandable>

  <Expandable title="How do I edit a discount?" default-open="false">
    On the Discounts page, open the discount's action menu and choose **Edit Discount**, or click the code. Change the fields, then click **Save**.
  </Expandable>

  <Expandable title="How do I delete a discount?" default-open="false">
    Open the action menu on the discount row and choose **Delete Discount**, then confirm. **Delete Discount** appears only for a discount that has never been used. Deleting cannot be undone, so use **Archive Discount** if you want to keep the history.
  </Expandable>

  <Expandable title="How do I archive a discount?" default-open="false">
    Open the action menu on the discount row and choose **Archive Discount**. The discount stops applying to new checkouts and keeps its usage history.
  </Expandable>

  <Expandable title="How do I make a discount available to parents in the portal?" default-open="false">
    Set **Allow On Portal?** to **Yes** when you create or edit the discount. Parents can then enter the code during checkout in the parent portal.
  </Expandable>

  <Expandable title="How do I make a discount staff-only?" default-open="false">
    Set **Allow On Portal?** to **No**. Staff can then apply it from a profile, and parents cannot use the code.
  </Expandable>

  <Expandable title="How do I limit how many times a discount can be used?" default-open="false">
    Enter a number in **Limit** when you create or edit the discount. After that many uses, it stops working. Leave it blank or enter `0` for no limit.
  </Expandable>

  <Expandable title="How do I cap how many dollars a discount can give away?" default-open="false">
    Enter a dollar amount in **Maximum Total** when you create or edit a code discount. Leave it blank for no dollar cap. Sibling discounts do not use this field. See **Maximum Total** above.
  </Expandable>

  <Expandable title="How do I set a discount to expire on a certain date?" default-open="false">
    Set **End Date** when you create or edit the discount. The discount does not apply after that date. Set **Start Date** to control when it becomes active.
  </Expandable>

  <Expandable title="How do I create a percentage discount?" default-open="false">
    Enter the percentage in **Percent**, such as `10` for ten percent off, and leave **Fixed Amount** blank or at `0`. Only one of the two can be greater than zero.
  </Expandable>

  <Expandable title="How do I set up a pay in full discount?" default-open="false">
    For the automatic discount when a family chooses pay in full, click **Pay In Full Default** on the Discounts page, set the type and value, and click **Save Pay In Full Default**. Then set **Enable Pay In Full Discount** to **Yes** on the form's **Settings** tab. See the **Configure a pay in full discount** step in **Create a new discount**.
  </Expandable>

  <Expandable title="How do I apply a discount to only certain products?" default-open="false">
    Use **Apply Only To These Products** to pick the products that qualify. Leave it blank to apply the discount to all eligible products. This is separate from **Apply To All Sessions**, which only affects how a percent discount spreads across a child's sessions.
  </Expandable>

  <Expandable title="How do I set up a multi-session discount?" default-open="false">
    On the Discounts page, click **Multi-Session**, then **Add Multi-Session Discount**. Name the rule, set **Minimum Sessions**, and add tier rows that link session counts to existing discount codes. See **Create a multi-session configuration** above.
  </Expandable>

  <Expandable title="How do I stop a discount from being used?" default-open="false">
    Archive the discount, set **Status** to **No Longer In Use** on **Edit Discount**, set an **End Date** in the past, or set **Limit** to a number already reached. Archiving stops new use and keeps the history.
  </Expandable>

  <Expandable title="Can the same family use a discount more than once?" default-open="false">
    Yes, if **Allow Duplicate?** is **Yes** on the discount. Set it to **No** to limit the discount to one use per user.
  </Expandable>

  <Expandable title="How do I preview a discount before saving?" default-open="false">
    Open **Add New Discount** or **Edit Discount**, fill in your settings, then use the **Preview** panel to pick real people and sessions. Click **Calculate** to see how the discount applies at checkout. See **Discount Calculator** above.
  </Expandable>

  <Expandable title="How do I test a discount before saving?" default-open="false">
    Use the **Preview** panel in the discount editor. It runs the checkout pricing engine against the people and sessions you pick, so you see the real amounts without creating any records. See **Discount Calculator** above.
  </Expandable>

  <Expandable title="Why is my discount code not working?" default-open="false">
    Click **Code Checker** on the Discounts page. Pick the discount, select the products, optionally pick a camper, then click **Run check**. The checker lists every issue by severity. See **Discount Checker** above.
  </Expandable>

  <Expandable title="How do I check a discount code problem?" default-open="false">
    Go to **Admin → Discounts** and click **Code Checker**. Pick the discount, select the products to test, optionally pick a camper, then click **Run check**. Errors are listed first. See **Discount Checker** above.
  </Expandable>

  <Expandable title="How do I skip a deposit with a discount?" default-open="false">
    Set **Bypass payment at portal checkout?** to **Yes** when you create or edit the discount. Parents can then submit their registration without entering a card or ACH payment. You can also add a dollar or percent credit. See **Bypass payment at portal checkout** above.
  </Expandable>

  <Expandable title="How do I make a discount waive the deposit?" default-open="false">
    Set **Bypass payment at portal checkout?** to **Yes** on the discount. There is no separate "Skip Deposit?" toggle. This one field lets the family submit checkout without paying. See **Bypass payment at portal checkout** above.
  </Expandable>
</ExpandableGroup>
