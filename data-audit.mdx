## What Data Audit shows

**Data Audit** lists changes to profile field values for people in your camp. Use it when you need to see what a field used to be, who changed it, and when.

Open **Admin → Data Tools & Activity → Audit**. The page title is **Data Audit**.

You need the custom module / Data Tools access that grants **Audit** in the sidebar (the same permission that opens this page).

## Read the list

The date range at the top defaults to the last 30 days and limits every search and the **Field** list. Each page of results loads from the server as you page or filter.

Each row typically shows:

- The person's **Name** (opens their profile)
- The **Date** of the change
- The **Field** that changed
- The **Old Value** and **New Value**
- **Changed By** (opens that staff profile when it is a person)

Use the search box (**Name, field or value**) and the **Field** dropdown (default **All fields**, plus every field name that changed in the selected dates) to narrow the list. Empty state: **No changes match these filters and dates.**

## Restore an old value

Every row shows a **Restore old value** button. When a restore is not allowed, the button stays visible but disabled, and the hover tip explains why. Restorable rows are text-style profile answers (including dropdown and multi-select) where the old value is still readable and was not truncated, and was not part of a season snapshot restore path.

1. Find the change you want to undo.
2. Click **Restore old value**.
3. Confirm with wording like Set Grade for Jordan back to "5th"? (field, name, and old value filled in) and **Yes, restore it**.
4. On success, Campium shows a message such as Grade is back to "5th". and the list refreshes.

If the value cannot be restored, leave the button disabled or, after you try, you may see **The value could not be restored.**

## Restore several changes at once

Use bulk restore when a bad import or mass edit touched many rows.

1. Tick the checkbox on each change you want to undo, or use the page checkbox (**Select the changes on this page**). Ticks carry across pages and clear when you change **Field**, Filter, or the date range.
2. Click **Restore selected** (the badge shows how many you picked), or **Restore all matching** for every row that matches the current dates, **Field**, and Filter.
3. Review the preview of how many will restore and how many will be skipped, then confirm with **Yes, restore them** (or **Yes, restore it** for a single row).
4. Watch **Restoring…** until you see **Restore finished** (or **Restore stopped** if you cancel).

A text, date, or dropdown field that changed several times goes back to its oldest old value. If that oldest row cannot be restored, later rows for the same field are skipped too, so a restore never puts the import's own value back. Multi-select rows each re-add their option. Preview is capped at 5,000 matching rows. Empty selection shows **Nothing to restore**.

<Callout kind="alert" collapsed="false">
  Restoring writes the old answer back onto the live profile. Confirm you have the right people and fields before you click **Yes, restore it** or **Yes, restore them**.
</Callout>
