## Overview

Seasons help you organize activity periods so families and staff work within the right timeframe. Use seasons to keep current offerings visible, control where a season appears in the admin experience, and decide when an older season should no longer stay active.

<Callout kind="info" collapsed="false">
  Labels or layout can vary slightly by setup, but the workflow is the same. Use the **Seasons** area to review your season list, open an existing season, or select **Add New Season** to create one.
</Callout>

## Season setup

Click a season name on **Seasons** to open the six-step setup workspace (**Season**, **Sessions**, **Form**, **Payment plans**, **Discounts**, **Review**). You land on the **Sessions** step. The row menu still offers **Guided setup**, which opens the same place.

Older session and subproduct list pages redirect into this workspace.

For the full walkthrough, see [Guided Season Setup](/guided-season-setup).

## Create a new season

Create a new season from the Seasons list when you need a new registration period, program cycle, or membership timeframe.

<Steps>
  <Step title="Open the Seasons area" icon="folder" title-type="p">
    - Go to the **Seasons** area in the admin site.

    - Review the list of existing seasons so you can confirm whether you need a new one or need to update an existing season instead.
  </Step>

  <Step title="Start a new season" icon="plus" title-type="p">
    - Select **Add New Season**.

    - A season form opens where you can enter the season settings.
  </Step>

  <Step title="Enter the season settings" icon="edit" title-type="p">
    The **Add New Season** modal keeps the create step short. It has these fields:

    - Add the **Season Name**.

    - Set the **Season Start Date** (required). Helper text: **When the first registration begins.**

    - Set the **Season End Date** (required).

    - Set whether the season is a **Membership Season**.

    Reports and season windows use start through end, so both dates are required and the end date must come after the start date. If either date is missing, Campium shows **You must enter a season start date.** or **You must enter a season end date.**

    <Callout kind="info" collapsed="false">
      The financial-snapshot, dropdown, and status settings do not appear when you first create a season. They become available in the **Edit Season** modal after the season exists.
    </Callout>
  </Step>

  <Step title="Save the season" icon="check-circle" title-type="p">
    - Save your changes.

    - After saving, the new season appears in the season list and is available based on the settings you selected.
  </Step>
</Steps>

## Season settings

Use these settings to control how the season appears and how your team uses it.

- **Season Name** — The name of the season as it appears in the admin area. Use a clear name your staff will recognize quickly.

- **Season Start Date**: Required. Marks when the first registration begins. The Seasons list shows a **Start Date** column. **Edit Season**, Guided setup **Season** (**Start date**), and **Copy Season** (**New Season Start Date**, when you create a new season) use the same rule.

- **Season End Date**: Required. Sets the date the season runs through. Must come after **Season Start Date**.

### Edit dates on the Seasons list

On **Seasons**, click a cell in the **Start Date** or **End Date** column to change that date without opening the full season editor. Empty cells show **None set**. Enter the date, then **Save** (or **Cancel**). Season start and end are required, so you cannot clear a date once it is set. You can still set or change both dates from **Edit Season** and Guided setup.

If an active season is missing either date, admins can see a one-per-day **Quick reminder** that says at least one active season is missing its **Season Start Date** or **Season End Date**, and to click the green **Active** button next to a season to open it and set both dates. Reports use the start date through the end date, so filling these in keeps reporting and reminders accurate.

On dashboard year-over-year cards, **Pace start (optional)** lets you override when pace charts begin. Helper text: **Leave blank to use the season's start date.** Those cards show a **Using dates:** footnote with each selected season's charted range. An estimated range is labeled **(estimated)**. Hover the footnote for why each end was chosen. Click it to open that card's season settings gear so you can adjust dates or pace start without leaving the dashboard.

- **Show In Financial Snapshot On Dashboard** - Controls whether this season appears in the **Financial Snapshot** card on the dashboard. Available when editing an existing season. On that card you can toggle **Receivables** (headline **Total Accounts Receivable**) and **Credits** (headline **Total credits held**). Selecting a season opens the matching report for that view.

- **Show In Dropdowns On Admin Site** — Controls whether staff can select this season from season dropdown lists in the admin site. Available when editing an existing season.

- **Membership Season** — Marks the season as a membership season when that applies to how you use seasons.

- **Status** — Sets whether the season is currently active or inactive. Available when editing an existing season. Keep this set carefully, because changing it can affect camper and staff status.

## Set a season inactive only after it has passed

Set a season to inactive when you no longer want it treated as a current active season. This is usually something you do after the season has ended.

When a season's **Season End Date** has passed and the season is still **Active**, Campium emails people with the **Administrator** role a reminder. Starting 14 days after the end date you may see a subject such as **Reminder:** followed by the season name and **is still marked active**. Starting 30 days after the end date, a last reminder can follow. The email includes an **Open Seasons** link that takes you to the Seasons page. Once you close the season (**Inactive**), those reminders stop. Campium manages the wording of that reminder for you.

<Callout kind="alert" collapsed="false">
  Closing a season from **Active** to **Inactive** sets campers who are not also in another **Active** season to **Inactive**. Staff inactivation is optional on the Close season page. Only close a season after it has passed.
</Callout>

If you are unsure whether campers or season-assigned staff still rely on the season, confirm that another active season already applies before you close it.

## Close a season

Closing a season no longer happens only inside the **Edit Season** modal. Choosing **Inactive**, or **Close Season** from the season row menu, opens a dedicated **Close season** page. Nothing changes until you click the red **Close** button at the bottom (it includes the season name) and confirm.

You can open that page from:

- The season row menu → **Close Season**
- **Edit Season** or Guided setup **Season** → set **Status** to **Inactive**
- A **Review and close** link that includes the season name, when Campium offers it

You need access to **Seasons** (the product module). Staff Hub names on the status step need **Staff Hub** access.

### What the Close season page covers

The page title area includes **What closing … does** (with the season name), **Download everything (CSV)**, and a link **How closing a season works**. Counts at the top show how many forms go offline, campers become Inactive, staff become Inactive, and Staff Hub statuses change. Helper text: counts are as of today, and nothing changes until you close.

Read each numbered section, change the options you need, then close:

1. **Forms go offline** - Checkbox like **Take 3 forms in Summer 2026 offline (sets them to Hidden)** (count and season name match your season). Uncheck to leave forms as they are. Reopening the season does not bring forms back; turn each form on from its settings.
2. **Campers become Inactive** - Active campers who are not in another active season become Inactive (including campers with no season on their profile). Parents whose family has no active camper left become Inactive too, unless they are also staff or an admin.
3. **Staff become Inactive** - Optional. **Inactivate staff who have** the season **on their profile** (checked by default when anyone qualifies). Separate option: **Also inactivate staff with an approved application on a form**, then **Choose a form**. Staff in another active season stay active.
4. **Profile data snapshot** - Saves profile answers at the close for reporting. If a snapshot already exists, choose **Take a new snapshot now** or **Keep the snapshot from** the earlier capture date. If you froze early, choose **Keep it and lock it** or **Replace it with a new snapshot**.
5. **Staff Hub application status** - Hired staff become **Returning**; others are cleared except statuses you keep in Staff Hub settings (**DNR**, **Fired**, and **Dismissed** always stay). If you keep an existing snapshot in step 4, statuses do not change. See [Staff Hub](/staff-hub#choose-which-fields-and-statuses-appear).

Footer actions: **Cancel** and the red **Close** button with the season name. You confirm once more before anything runs.

If the season is already Inactive, the page explains that it was closed before and nothing here runs. If it was closed and later reopened, a note says reopening did not undo that close.

## Email an invoice to families registered for the season

The **Edit Season** modal still includes an **Email invoice to all families registered for season** checkbox (this is separate from closing the season). Check it when you want every family registered for the season to receive their current invoice by email as part of saving other season settings.

When you check it, an optional message field appears so you can add a short note that is included with the emailed invoices. Leave the message blank to send the invoices without extra wording, or leave the checkbox unchecked to save without emailing anyone.

## Freeze a running season's data

Use this when you open the next season for registration before the current season ends, and you still need to edit the running season's profile answers.

On an **Active** season that does not already have a snapshot, **Edit Season** shows **Opening next season before this one ends?** with **Freeze this season's data**. Helper text: **Take a snapshot of this season's profile data now so you can keep editing it after next season's registration opens, while the season stays active.**

1. Open **Seasons**, then **Edit Season** for the active season.
2. Click **Freeze this season's data**.
3. Confirm **Freeze this season's profile data now? From then on, every profile and custom report asks which season you are editing.** with **Yes, freeze it**.
4. Campium shows **Snapshot queued. It builds in the background, and you can edit this season's data once it is ready.**

After the freeze is ready:

- On the **Seasons** list, under **Status**, the season shows a **Frozen (editable)** badge. Hover it for when the freeze was captured and a reminder that profiles and custom reports ask which season you are editing.
- Profiles and custom reports ask which season you are editing (**Current data** vs the frozen season).
- Editable freeze options in reports are labeled with the season name and **(you can edit this season)**.
- On a profile, seasons and products for that frozen season stay in sync with session changes (helper: **Updates when this season's sessions change**). Other snapshot fields that cannot be edited show **Can't be changed for this season**.
- When you later set the season to **Inactive**, helper text explains that keeping the early freeze **adds anyone who enrolled since and makes it read-only**.

You need access to manage seasons (the same permission as the **Seasons** area). Freezing is only offered while the season is **Active** and no snapshot already exists.

## Use profile-data snapshots for historical reporting

When you close a season on the **Close season** page, Campium takes a snapshot of the profile data (unless you already froze the season early and choose to keep that freeze). Step **4 Profile data snapshot** lets you take a new snapshot or keep an existing one. The snapshot builds in the background after you close.

Later, custom reports can use that saved snapshot to filter profile data based on what was true at the time the snapshot was taken. This is useful when profile details may change over time and you need reporting based on the earlier values.

<Callout kind="alert" collapsed="false">
  A snapshot does not finish until after you close the season, and it runs in the background. Use it when you want reporting to reflect profile data as it existed at that specific point in time.
</Callout>

### Watch snapshot status on the Seasons list

After you queue a snapshot, the **Seasons** list shows status under that season's **Status** link. Queued, building, and failed states use a badge. When the snapshot finishes, the list shows muted helper text **Snapshot ready** instead of a badge (hover for the capture time). Status updates on its own while the snapshot is still working.

| Status | Meaning |
| --- | --- |
| **Snapshot queued** (badge) | The snapshot is waiting to start. |
| **Snapshot building** (badge) | The snapshot is copying profile answers in the background. |
| **Frozen (editable)** (badge) | You froze this season early while it is still **Active**. Profiles and custom reports ask which season you are editing. |
| **Snapshot ready** (helper text) | The snapshot finished. On a custom report, set the **Season** filter to this season, then choose its close under **Profile answers as of**. |
| **Snapshot did not finish** (badge) | The snapshot failed. Open **Edit Season** to retry. |

Click a queued, building, or failed badge (or the season status) to open **Edit Season**. **Snapshot ready** helper text is informational; open **Edit Season** from the season status link if you need details.

### Review or retry a snapshot in Edit Season

In **Edit Season**, the **Profile data snapshot** section shows the same badge plus details for that season's latest snapshot:

- When the snapshot is **ready**, you see when it was captured, how many saved answers it holds, and a reminder to set the **Season** filter to this season on a custom report, then choose its close under **Profile answers as of**.
- When it is still **queued** or **building**, you see when it was queued and that the seasons list will update when it finishes.
- When it **did not finish**, you see that there is nothing to report on from it, plus **Retry snapshot**.

To retry a failed snapshot:

1. Open **Edit Season** for that season.
2. Under **Profile data snapshot**, select **Retry snapshot**.
3. Confirm with **Yes, retry it** when asked **Put this snapshot back in the queue?**
4. Campium shows **Snapshot queued again. It will rebuild in the background.** and reloads the season panel.

## When snapshots run

Campium queues a profile-data snapshot when you close a season on the **Close season** page (Active to Inactive). That is most useful when historical profile values matter for reporting, especially if family profile information may change after the season closes. If a snapshot already exists, you choose whether to keep it or take a new one before you close.

## Summary

Manage seasons from the **Seasons** area in the left hand navigation by creating new records, updating the visible season settings, and closing seasons only after they have passed. Closing an active season queues a profile-data snapshot so later reports can reflect profile information as it was when you closed.

## FAQ

<ExpandableGroup>
  <Expandable title="Can I run a report using season data from a previous point in time?">

  Yes. When you close a season, Campium captures a profile-data snapshot (unless you keep an existing one). On a custom report, set the **Season** filter to that season, then choose its close under **Profile answers as of**. The exact historical views available depend on the reports your organization has access to.

  </Expandable>

  <Expandable title="Can I see what this season looked like last week/month?">

  You may be able to review historical reporting based on a snapshot taken when the season was saved. Exact point-in-time views for a specific week or month depend on the reporting tools available in your organization.

  </Expandable>

  <Expandable title="How do I view historical answers campers/parents submitted in the past?">

  Use reporting that references the saved profile-data snapshot for the season. That snapshot reflects profile data captured at save time, but which historical answers you can view depends on the reports available to your organization.

  </Expandable>

  <Expandable title="Can I compare current season answers to an earlier snapshot?">

  Yes. On a person's profile, open **All User Data** (or a custom data view). When ready snapshots exist for that person, choose a season from the **Season snapshot** menu next to **Filter by profile field**. Current answers stay editable on the left; the snapshot values appear on the right, with a **Changed** badge where they differ.

  Snapshots come from closing a season (Active to Inactive), or from **Freeze this season's data** while the season is still active. See [Profiles](/profiles#tabs-and-sections) for the comparison view.

  </Expandable>

  <Expandable title="Can I restore or view a prior version of season data without overwriting current data?">

  This page only describes snapshots for historical reporting of profile data captured when the season is saved. Restore workflows or prior-version viewing may depend on features and access not described here.

  </Expandable>

  <Expandable title="Does snapshot data include forms, registrations, balances, and custom field answers?">

  The page confirms snapshots are used for profile-data reporting after the season is saved. Whether forms, registrations, balances, or custom field answers are included depends on how your reports use snapshot data in your organization.

  </Expandable>

  <Expandable title="How far back can snapshots go for a season?">

  Snapshot history depends on when snapshots were created and what reporting history your organization retains. This page does not define a specific retention window.

  </Expandable>

  <Expandable title="How often are season snapshots created?">

  The page describes a snapshot that runs in the background after you close a season. It does not indicate that snapshots run on a recurring schedule, so snapshot frequency depends on when you close seasons.

  </Expandable>

  <Expandable title="Can I choose exact date/time snapshot when running exports or reports?">

  Exact date and time selection for reports or exports may depend on the reporting tools available in your organization. This page only confirms that snapshot data is captured when the season is saved.

  </Expandable>

  <Expandable title="How do I find participant answers as they were on a specific date?">

  Start with reporting that uses season snapshot data captured when the season was saved. If you need an exact date-based view, availability depends on the report filters and historical reporting options in your organization.

  </Expandable>

  <Expandable title="Why does my current report not match a past snapshot report?">

  Current reports may reflect updated profile data, while a snapshot report reflects profile data captured at the time the season was saved. Differences can also come from report filters, report type, and available historical data.

  </Expandable>

  <Expandable title="Can I audit what changed between two snapshot dates?">

  Change auditing between snapshot dates may be available in some reporting workflows, but this page does not describe that capability. What you can audit depends on the reports and access available in your organization.

  </Expandable>

  <Expandable title="Are snapshot reports read-only, or can they change live season data?">

  Most snapshots are saved history and stay read-only. If you froze a season early with **Freeze this season's data**, you can still edit that season's profile answers from a profile or custom report until you close the freeze (for example when you close the season).

  </Expandable>

  <Expandable title="Who can access season snapshots and historical reporting?">

  Access to season snapshots and historical reporting depends on the permissions and reports available in your organization. If you cannot find a snapshot-based report, check with your administrator.

  </Expandable>

  <Expandable title="Can I download/export historical snapshot results?">

  Export options depend on the reports and access available in your organization. If a report supports historical snapshot data, any download or export workflow depends on that report's available actions.

  </Expandable>
</ExpandableGroup>
