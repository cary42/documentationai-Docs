## What Portal Settings control

Portal Settings control how your parent portal presents itself to families. From this screen you can upload the favicon that appears in the browser tab, set the home page heading and instructions (with a name bar colour and live preview), and choose which user types families can select when they sign in or register.

<Callout kind="info" collapsed="false">
  Portal Settings require the site text permission. If you do not have access, you are redirected away from the page. Ask a Campium administrator on your team if you need access.
</Callout>

## Open Portal Settings

Go to **Portal → Settings** in the left navigation. The page title is **Portal Settings**. The screen is organized into cards for the favicon, the **Home page** (Beta), and login user types.

<Callout kind="info" collapsed="false">
  Some portal options depend on how your account is set up. If the login user types card is not available, you see a message that portal settings are not available for your account yet.
</Callout>

## Favicon

The favicon is the small icon shown in the browser tab and on the iOS home screen when a family saves your portal. Setting your own favicon makes the portal feel branded to your camp.

<Steps>
  <Step title="Review the current favicon" icon="monitor" title-type="p">
    In the **Favicon** card, the current icon is shown. If you have not set one, the card notes that the default Campium favicon is in use.
  </Step>

  <Step title="Choose an image" icon="upload" title-type="p">
    Under **Upload favicon**, select an image file. Accepted formats are ico, png, jpg, and gif, with a maximum size of 1 MB. A square image of 32 by 32 pixels or larger is recommended.
  </Step>

  <Step title="Upload" icon="check-circle" title-type="p">
    Click **Upload**. The new favicon replaces the previous one on your portal.
  </Step>
</Steps>

<Callout kind="tip" collapsed="false">
  Browsers cache favicons aggressively. After uploading, families may need to refresh or reopen the portal before the new icon appears in their tab.
</Callout>

## Home page (Beta)

The **Home page** card controls what families see above their list of names on the parent portal home page. It carries a **Beta** badge. Heading and instructions also appear on the classic home page. **Name bar colour** colours the name row on the updated home layout shown in the live preview.

From **Portal → Portal Site Text**, an info note explains that the home page heading and the instructions under it are now set here. Use **Open Home page settings** to jump to this card.

<Steps>
  <Step title="Open the Home page card" icon="home" title-type="p">
    On **Portal → Settings**, find the **Home page** card. Helper text: *What families see above their list of names on the parent portal home page.*
  </Step>

  <Step title="Set the heading" icon="edit" title-type="p">
    In **Heading**, enter the title above the name list. Placeholder: **Your family**. Helper text: left as **Forms** or blank, families see **Your family**. This is also the heading on the classic home page.
  </Step>

  <Step title="Set the instructions" icon="edit" title-type="p">
    In **Instructions**, enter the line under the heading. Placeholder: **Tap a name to see and finish their forms.** Helper text: left blank, families see that same default line. This is also shown on the classic home page.
  </Step>

  <Step title="Choose a name bar colour" icon="droplet" title-type="p">
    Under **Name bar colour**, pick a swatch. Every colour here meets accessibility contrast rules. Use **Revert to the default colour** to clear a custom choice.
  </Step>

  <Step title="Check the live preview" icon="monitor" title-type="p">
    Watch **Live preview** on the right. It updates as you change the heading, instructions, and colour.
  </Step>

  <Step title="Save" icon="check-circle" title-type="p">
    Click **Save**. One save writes the heading, instructions, and colour together.
  </Step>
</Steps>

<Callout kind="tip" collapsed="false">
  The live preview defaults match the updated home layout. If you leave **Heading** as **Forms** or blank, or leave **Instructions** blank, families on that layout see **Your family** and **Tap a name to see and finish their forms.**
</Callout>

## Login user types

The login user types card controls which user types appear under **I am a** when someone opens **Create account** on your parent portal. For example, you might show Parent and Staff but hide types that do not register through the portal.

A **live preview** on the right shows how those types look in the registration chooser and updates as you make changes. On the live portal login page, types appear as selectable chips rather than a classic dropdown.

<Callout kind="info" collapsed="false">
  At least one user type must be shown. You cannot save with every type turned off, because families would have nothing to select at registration.
</Callout>

### Configure which types appear

<Steps>
  <Step title="Show or hide each type" icon="settings" title-type="p">
    In the **Show** column, use the checkbox on each row to include or exclude that user type from the portal login and registration screens. Rows you turn off appear dimmed, and their label and order fields are disabled.
  </Step>

  <Step title="Set a login label" icon="edit" title-type="p">
    In the **Login label** field, enter the wording families should see for that type. Leave it blank to use the user type's own name. This lets you show friendlier wording without renaming the underlying type.
  </Step>

  <Step title="Set the display order" icon="filter" title-type="p">
    In the **Order** column, enter a number to control where the type appears. Lower numbers appear first. Use this to put the most common choice at the top.
  </Step>

  <Step title="Check the live preview" icon="monitor" title-type="p">
    Watch the **Live preview** panel and confirm the labels and order match what you want families to see.
  </Step>

  <Step title="Save your changes" icon="check-circle" title-type="p">
    Click **Save**. Your choices apply to the parent portal **Create account** flow.
  </Step>
</Steps>

<Callout kind="tip" collapsed="false">
  Only show the user types that actually register or sign in through the portal. A shorter, clearer list reduces confusion and mis-registrations.
</Callout>

## Fields in the login user types table

<ParamField body="Show" param-type="toggle" required="true" deprecated="false">
  Whether this user type appears on the portal login and registration screens. At least one type must be shown.
</ParamField>

<ParamField body="User Type" param-type="text" required="true" deprecated="false">
  The name of the user type as defined in your account. This is read-only here and is used as the default label when no login label is set.
</ParamField>

<ParamField body="Login label" param-type="text" required="false" deprecated="false">
  Optional wording shown for this type under **I am a** on **Create account**. Leave blank to use the User Type name.
</ParamField>

<ParamField body="Order" param-type="number" required="false" deprecated="false">
  The position of this type in the list. Lower numbers appear first.
</ParamField>
